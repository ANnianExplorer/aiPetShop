# S1.41 · 桌宠动物形象与右键动作菜单

- 批次：S1.41
- 日期：2026-11-24
- 状态：已完成
- 来源：用户点名（「修改 app 内宠物形象，用宠物来展示，同时支持鼠标右键切换动作，目前你这个宠物还是太丑了」）
- 关联：`docs/plans/s1.22-pet-engine.md`、`docs/plans/s1.35-chat-a11y.md`

## 目标

1. 默认桌宠不再是一个绿发人形角色，而是按当前宠物类型显示动物：猫 → 橘猫、狗 → 柴犬、其他/未知 → 奶油兔。
2. 用户在 `/pet-studio` 生成过自定义精灵图时，继续优先用自定义图；内置动物只做兜底。
3. 在桌宠上点鼠标右键打开动作菜单，可切换吃白饭、跳舞、转圈、伸懒腰、摸头、睡觉/叫醒；保留原有长按打开。
4. 菜单支持键盘（Enter、ContextMenu 键、Shift+F10 打开，Escape 关闭，点外部关闭），并读得出按钮名称。
5. 菜单固定在视口内，不被右下角宠物顶出屏幕；右键/长按统一在宠物上方展开，不遮住宠物本身。

## 取舍

- **手绘 SVG，不接生成式美术**：三只动物用同一套线条/配色，体积小、可离线、可进 Git；不引入图片生成依赖。
- **不改用户照片链路**：`Pet.avatar` 是带背景的上传图，直接塞进 canvas 会出现「方形照片框」；继续让 `PetStudio` 负责抠图/卡通化，未生成时才用内置动物。
- **动作复用引擎已有片段**：`act.eat`、`act.dance`、`act.spin`、`act.stretch`、`click.pat` 都已在 `clips.ts` 中，不新增动画代码，只做菜单编排。
- **菜单用原生 button + 文本**：图标是装饰，按钮本身有中文名；不引入第三方菜单库，避免焦点管理失控。
- **删除旧 `lumina.svg`**：已无引用，保留只会让后来者以为默认形象还是它。
- **不做骨骼动画**：本轮只解决「丑」与「右键动作」；分部件动画、拖拽物理调参不在范围内。

## 风险

- **右键与长按共用菜单**：长按会先触发 `pointerdown` 的拖拽判定；菜单打开后 `pointerup` 会停止冒泡，避免误触聊天。触屏长按仍可用。
- **菜单定位**：`position: fixed` + 视口夹取；小屏（< 220px 高）时会被夹到左上角，菜单可能盖住宠物，属于极端尺寸降级。
- **图标字体**：Material Symbols 来自 Google Fonts；断网时会显示 ligature 文本。已加 `overflow:hidden` 防溢出，但离线环境图标仍不可用（全站同源问题，本轮不扩大范围）。
- **自定义精灵图**：PetStudio 生成的图仍是最高优先级；如果用户生成过一张人形图，仍会显示那张，这是用户自己的选择。
- **真实设备手势**：jsdom 只能验证事件契约；iOS Safari 长按/右键行为、触屏长按 520ms 的手感仍需真机验收。
