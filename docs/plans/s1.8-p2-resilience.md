## 1. 四项交付

### 1.1 真机落库（MySQL）

- 执行 `backend/sql/v2.10-agent.sql`、`backend/sql/v2.11-agent-memory.sql`；幂等（`CREATE TABLE IF NOT EXISTS`）。
- `REPO_BACKEND=mysql` 起服务，跑 `scripts/e2e_smoke.py`、`scripts/p1_smoke.py`、`scripts/admin_smoke.py`。
- 验收：三份冒烟全绿；`SELECT COUNT(*) FROM agent_run` 与冒烟里的 run 数一致；重启进程后会话仍可查（内存仓库做不到）。

### 1.2 Redis 兼容与真机事件总线

- `create_event_store` / `create_rate_limiter` 统一 `protocol=2`（RESP2），兼容 Redis 5。
- 加一个探测：连接时若服务端不支持 RESP3，回退 RESP2 并记一条 warning 日志，而不是抛错崩服务。
- 验收：`EVENT_BACKEND=redis`、`RATE_LIMIT_BACKEND=redis` 下，`e2e_smoke` 的续传用例（full/after/resume 等价）通过；重启 uvicorn 后 `GET /agent/runs/{id}/events?after=N` 仍能取到事件（证明事件不在进程内存）。

### 1.3 幂等键（重复提交不重复执行）

- `ChatRequest` 增可选 `client_message_id`（客户端生成的 UUID/短串，≤64）。
- 存储：`agent_run` 增 `idempotency_key VARCHAR(64)` + `UNIQUE KEY uk_idem (session_id, idempotency_key)`（`NULL` 不参与唯一）。
- 行为：同一 `(session_id, client_message_id)` 第二次提交 → **不再调模型**，直接按新 run 的 SSE 契约回放已有 run 的事件（`route → ... → done`），并把 `done` 里带 `replayed: true`。
- 验收：同一 key 连发两次，`SELECT COUNT(*) FROM agent_run WHERE idempotency_key=...` = 1，第二次响应 `replayed: true` 且不新增消息。

### 1.4 熔断（连续失败快速失败）

- 新增 `app/core/circuit.py`：`CircuitBreaker(name, threshold=5, cooldown_s=30, clock)`，
  状态 `closed → open（连续 N 次失败）→ half_open（冷却后放一个探测）→ closed`。
- 应用点：LLM 调用（`ModelError`）、Java 后端调用（`BackendError`）。
- 打开时抛 `ModelError`/`BackendError` 并带 `retryable=True`，`/readyz` 增加 `circuit` 检查项（open 时 `degraded`）。
- 验收：桩服务连续返回 500，第 6 次起立即失败（不等待超时），且 `pytest` 有用例覆盖 half-open 恢复。

## 2. 不做

- 不做多副本压测（本机单实例，只验证 Redis 事件总线语义）。
- 不做熔断的分布式共享状态（单实例内存计数足够；多副本需 Redis，留 P3）。
- 不动 Java 后端代码（本轮只在 Python 侧验证真机连通）。
