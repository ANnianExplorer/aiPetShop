# S1.39 全站导航 / 提示 / 设置页无障碍基线

- 状态：已完成（2026-11-23）
- 关联 BACKLOG：D10（全站无障碍审计，第一刀）
- 批次：s1.39
- 日期：2026-11-23
- 短名：a11y-nav-settings

## 目标

在不改变现有视觉与业务行为的前提下，把「全站都会经过」的三处交互补到可键盘操作、可被读屏感知：

1. 底部主导航：原生按钮语义、导航名称、当前位置 `aria-current`、装饰元素对辅助技术隐藏。
2. 全局 Toast：状态播报区（`role=status` + `aria-live=polite`），错误提示升级为 `role=alert`，关闭按钮有可读名称。
3. 通用设置页：唯一 `h1`、返回按钮名称、两个开关的 `role=switch` / `aria-checked` / `aria-disabled`、语言弹窗的 `dialog` 语义与焦点闭环。
4. 全局样式：统一 `:focus-visible` 焦点环；`prefers-reduced-motion: reduce` 下关闭动画/过渡/平滑滚动。

这是 D10 的「基线切片」：先覆盖全站外壳与一个代表性表单页，剩余页面（社区卡片、图片 alt、对比度、读屏人工验收）继续留在 BACKLOG。

## 现状与取舍

- 31 个 views 已有 `<main>`，但底部导航是 5 个 `<div @click>`：鼠标可用、键盘不可达，读屏听不到「导航」也听不到「当前页」。
- Toast 只有视觉呈现，没有 live region；错误与成功对读屏没有优先级差异。
- 设置页标题是 `<span>`，开关是裸 `<button>`（读屏只会念「按钮」），语言弹窗没有 `dialog` 语义，打开后焦点仍在背后页面。
- `style.css` 有大量动效，但没有减少动效分支；全局没有统一焦点环（部分输入框还 `outline-none`）。
- 取舍：本轮不引入 axe / 读屏自动化依赖，不做全站逐页改造；先把「外壳 + 设置页」做成可复制范式，并用 jsdom 单测锁住 DOM 契约。真实读屏（NVDA/VoiceOver）与对比度仍需人工验收，报告中如实标注。
- 导航从 `div` 改 `button` 会带入浏览器默认样式，需显式 `border-0 bg-transparent p-0 font-inherit` 之类重置；保留原有尺寸、圆角、动画 class，避免视觉回归。

## 实现

### 1. `src/layout/MainLayout.vue`

- `<nav aria-label="主导航">`（新增 `nav.main` 三语）。
- 每个 tab 由 `<div @click>` 改为 `<button type="button">`，保留 `@click="navigate(tab)"` 与全部 class；当前项加 `aria-current="page"`。
- 两个 ambient 装饰光晕加 `aria-hidden="true"`。

### 2. `src/components/common/Toast.vue`

- 容器（TransitionGroup 根节点）加 `role="status"`、`aria-live="polite"`、`aria-atomic="true"`。
- 单条 toast：`type === 'error'` 时加 `role="alert"`（错误需要立即播报），其余保持普通文本。
- 关闭按钮加 `:aria-label="t('common.close')"`（新增三语），图标 `aria-hidden`。

### 3. `src/views/profile/GeneralSettings.vue`

- 标题 `span` → `h1`，保持原 class。
- 返回按钮 `:aria-label="t('common.back')"`，图标 `aria-hidden`。
- 热点推送开关：`role="switch"`、`:aria-checked="notificationsEnabled"`、`:aria-disabled="true"`、`:aria-label="t('settings.hotPush')"`；保留点击弹「开发中」。
- 深色模式开关：`role="switch"`、`:aria-checked="isDark"`、`:aria-label="t('settings.darkMode')"`。
- 语言触发按钮加 `ref="langTrigger"` 与 `:aria-haspopup="'dialog'"`、`:aria-expanded="showLangPicker"`。
- 语言弹窗：外层遮罩保留点击关闭；面板加 `role="dialog"`、`aria-modal="true"`、`aria-labelledby="lang-dialog-title"`、`tabindex="-1"`、`ref="langDialog"`；标题加 `id="lang-dialog-title"`；关闭按钮加 `aria-label`。
- 打开：`nextTick` 后 `langDialog.focus()`；关闭：`closeLangPicker()` 统一收口，`nextTick` 后把焦点还给 `langTrigger`。
- `keydown`：`Escape` 关闭；`Tab` 在弹窗内循环（复用 ChatView 的 `focusableIn` 思路，内联实现，避免跨页抽 composable 的额外面）。

### 4. `src/style.css`

在文件末尾追加**不在 `@layer` 内**的规则（层外规则优先于 Tailwind utilities，能压过 `outline-none`）：

```css
:focus-visible {
  outline: 2px solid #4b6455;
  outline-offset: 2px;
}

@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

### 5. 三语

`zh-CN.json` / `en-US.json` / `ja-JP.json` 各新增：

- `common.close`：关闭 / Close / 閉じる
- `nav.main`：主导航 / Main navigation / メインナビゲーション

### 6. 测试

- `src/layout/MainLayout.spec.ts`：`nav` 有名称；5 个 `button[type=button]`；当前项 `aria-current=page`；点击非当前项 `router.push` 一次；点击当前项不 push。
- `src/components/common/Toast.spec.ts`：容器 `role=status` + `aria-live=polite`；error toast `role=alert`；关闭按钮有名称且点击后移除；卸载/推进定时器后不残留。
- `src/views/profile/GeneralSettings.a11y.spec.ts`：唯一 `h1`；返回按钮名称；两个 switch 的 `aria-checked` / `aria-disabled`；点深色开关后 `aria-checked` 翻转；语言弹窗 `role=dialog` + `aria-modal`；打开后焦点进入；`Esc` 关闭且焦点回到触发按钮；`Tab` 首尾循环。

## 风险

- 原生 `button` 的默认 `font` / `padding` / `border` 可能造成导航视觉偏移 → 显式重置并保留原 class，构建后人工核对（本轮无浏览器点击环境则如实说明）。
- 焦点还给触发按钮依赖 `nextTick`；若 Transition 离场期间元素仍存在，需在关闭后延迟到 DOM 更新完成（用 `nextTick`）。
- `prefers-reduced-motion` 用 `!important` 是全局兜底，可能影响后续新增动效的预期；这是有意的可访问性优先取舍。
- jsdom 无法验证真实读屏顺序与颜色对比度，只能锁 DOM 契约。

## 非目标

- 不改造社区卡片、日志卡片、图片 `alt`、表单错误播报等其余 20+ 处交互（D10 剩余）。
- 不引入 axe-core / Playwright a11y 扫描。
- 不改路由 `document.title`（另一条 D10 子项）。
- 不改业务逻辑、接口、后端。
