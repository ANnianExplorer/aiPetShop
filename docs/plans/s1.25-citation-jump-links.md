# S1.25 引用回跳：让 locator 变成 App 路由（BACKLOG C4）

> 批次：S1.25 ｜ 短名：citation-jump-links ｜ 日期：2026-11-14

## 1. 目标

对话里 `done.citations` 的每一条，点下去都能落到**能核对的页面**：

- 健康引用 → `/weekly-health-detail?petId=…&date=…`，并且那一天被框出来、自动滚到视野里；
- 帖子引用 → `/post/{id}`；
- 记录引用 → `/log/{id}`；宠物引用 → `/pet-detail/{id}`。

而且**新增一种引用来源时不用改前端**：路由由后端随引用一起给出。

## 2. 现状与缺口（改之前的源码事实）

| 事实 | 位置 |
| --- | --- |
| 前端只认 `kind === 'log'`，其余一律弹个 toast | `ChatView.vue:229-235`（`openCitation`） |
| `locator` 是给人看的字符串：宠物是 `"宠物档案"`、健康是 `"petId=5001"` | `app/tools/pet.py` 三个工具 |
| 健康详情页只读 `currentPet`，不接任何 query | `WeeklyHealthDetail.vue` 的 `onMounted` |
| 帖子工具根本不存在，`tools` 只有四个 | `app/tools/pet.py::build_registry` |

所以 C4 不是「前端加两个 if」：后端的 `locator` 语义本身要升级，帖子引用还得先有来源。

## 3. 取舍

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A 前端按 kind 硬编码 | `if kind==='post' push(/post/...)` | ✗ 每加一种来源改一次前端，两处真源迟早漂移 |
| B `locator` = App 内路由（选它） | 后端产出 `/xxx`，前端只判断能不能跳 | ✓ 一处定义；老数据靠 kind 兜底，不破历史会话 |
| C `locator` = 结构化对象（`{page, params}`） | 前端自己拼路由 | ✗ 契约变复杂，落库的 JSON 还要迁；收益不值 |
| D 只做健康不做帖子 | 少建一个工具 | ✗ 验收要求「帖子引用能跳到帖子详情」，绕不过去 |

**为什么后端给路由是安全的**：路由是纯展示层约定，不含鉴权信息；跳过去之后页面自己再拉数据、自己再校验归属（S1.10 的越权 404 不变）。

## 4. 设计

```text
工具产出 citation             后端                前端
{kind,id,label,locator:"/…"} → done 事件/库 → citationRoute() → router.push
                                                   │
                                          老数据/无路由 → null → 显示 label
```

不变量：

- **L1** `locator` 以 `/` 开头即视为路由，前端原样 push，不再改写；
- **L2** 没有路由形态 `locator` 的老引用，`log`/`post`/`pet` 按 kind 兜底（历史会话不失灵）；
- **L3** 兜不住就返回 `null`，界面显示 label，**不假装能跳**；
- **L4** 健康引用的日期取「周记录里的最大值」而不是“今天”——看板可能是补录数据；
- **L5** 帖子工具只读、不带宠物过滤（问的是“别人的经验”，按宠物筛会筛空）。

## 5. 实施

1. `app/tools/pet.py`：`_fmt_date()` 归一 Java 的两种日期形态；三个工具的 `locator` 改成路由；新增 `SearchPostsArgs` + `search_posts`（走 `POST /post/list/page/vo`）并注册。
2. `src/utils/citationRoute.ts`（新）：`citationRoute(citation): string | null`。
3. `ChatView.vue::openCitation` 改用 `citationRoute`。
4. `WeeklyHealthDetail.vue`：读 `petId`/`date` 两个 query，命中那天加 `ring-2 ring-primary` 并 `scrollIntoView`。
5. 三语文案各补一条 `search_posts` 工具名。
6. 测试：`tests/test_citations.py` 7 例（四种 locator + 总闸 + 日期归一）、`test_api.py` 与 `test_graph_l2.py` 的工具集合、`citationRoute.spec.ts` 5 例。

## 7. 风险

| 风险 | 处置 |
| --- | --- |
| 路由拼错，点了 404 | 路由常量集中在工具层；`test_every_locator_is_an_app_route` 挡“写成人话”的回归；真机跳转仍要人工点一次 |
| 老会话引用没有路由 | L2/L3 兜底，最差退回原行为（显示 label） |
| 帖子工具把无关内容引进来 | 只读、默认为空关键词取最新 3 条；`extra="forbid"` 挡伪造字段 |
| 健康页高亮依赖日期字符串格式 | `_fmt_date` 归一 + 前端 `slice(0,10)` 双保险 |
| 多宠物 | `petId` 由工具带出，页面优先用 query 而不是当前宠物 |
