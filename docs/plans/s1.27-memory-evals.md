# S1.27 记忆抽取评测：从「记录了几轮」到「抽对了什么」（BACKLOG C3）

- 状态：已完成
- 日期：2026-11-15
- 对应条目：BACKLOG C3「记忆抽取质量评测偏薄」
- 预算：单轮夜间维护（约 2 小时）

## 1. 问题

`evals` 的 `memory` 套件原来只有 2 条用例，而且两条测的都是「这轮对话有没有落进 history」——
那是管道连通性，不是记忆质量。`app/memory/extract.py` 里的 8 条正则规则从来没有被
「一句话里到底该抽出什么」这种带标注的语料量过，于是：

- **抽错值**没人知道：库里只会有「自信的假事实」，还会被画像当证据用；
- **抽漏**没人知道：表现为「聊了三轮它还是记不住」，只能靠用户投诉发现；
- **否定句最危险**：「对鸡肉不过敏」如果被抽成 `allergy=鸡肉不`，等于把一个错误长期写进档案。

## 2. 目标

1. `memory` 套件 ≥ 40 条、阈值 0.9（对齐 BACKLOG C3）；
2. 用例覆盖三类真实句式：**否定**（不过敏 / 不喜欢 / 不叫）、**多宠物**（换 pet_id 不串味）、**方言**（粤语 / 西南官话的常见说法）；
3. 跑出来的真实缺陷在 `app/memory/extract.py` 里修掉，每条配单测；
4. 评测体量变大后仍然纯离线（不碰真模型、不碰网络），CI 里秒级跑完。

## 3. 方案与取舍

### 3.1 三种用例形状

| 形状 | 测什么 | 怎么判 |
|---|---|---|
| `text` | 抽取质量 | `extract(text)` 的 key→value **完全等于** `expect`；`forbid` 列的 key 一个都不许出现 |
| `observe` | 服务层：多宠物隔离 / 重复说幂等 / 置信度过滤 | `MemoryService.observe` 跑完后的 `pet_id → (key→value)` 必须等于 `expect.pets` |
| `turns` | 历史完整性（原有 2 条保留） | 落库消息条数 = 轮数 × 2 |

`text` 用**全等**而不是「包含即通过」：多抽一个 key 就是假事实，必须红。

### 3.2 为什么直接测 `extract()` 而不走 HTTP

`extract` 是纯函数，记忆质量的全部决定都在这里；套一层 `POST /agent/chat` 只会把
`ScriptedModel` 的剧本和 SSE 解析噪声带进失败原因。HTTP 路径已被 `turns` 形状和
`tests/test_memory_api.py` 覆盖，不缺这一层。

### 3.3 拒绝的选项

- **LLM-as-judge**：不可复现、每次要花 token、CI 无 key 就挂。评测是回归门禁，不是「再问一次模型觉得对不对」。
- **只加用例不修规则**：等于给现有缺陷拍快照、把它们写进 `expect` 当预期行为。所以 `expect` 只写「人话应该抽出什么」，规则去对齐它。

### 3.4 阈值 0.9 的代价（写清）

C3 要求阈值 0.9。在 40+ 条确定性用例上，0.9 意味着**最多 4 条回归可以装成绿灯**。
接受这个代价，是因为用例按真实口语写、规则改动会一次性打红一片，不会刚好只红 4 条；
同时报告里必须写清「本轮实际 = 100%」，不拿阈值当遮羞布。
以后要更严把阈值调回 1.0 是一行改动，代价是任何新口语句式都会红。

## 4. 验收标准

| # | 断言 | 怎么验 |
|---|---|---|
| A1 | `python -m evals.run --suite memory` 用例数 ≥ 40、通过率 100% | 命令输出 |
| A2 | 否定 / 多宠物 / 方言三类各 ≥ 4 条 | `cases.jsonl` 按 id 前缀数（`mem-neg-`、`mem-multi-`、`mem-dialect-`） |
| A3 | 本轮修掉的每个缺陷都有单测，且修之前是真的红 | 先跑失败用例贴输出，再修 |
| A4 | `python -m pytest` 全绿、`ruff check .` 全绿 | 命令输出 |
| A5 | `python -m evals.run`（全部套件）仍绿，routing/safety 不受影响 | 命令输出 |

## 5. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 用例过分贴近正则，变成「给自己出题」 | 评测虚高 | 先按口语写句子再跑；失败原因归类，不为迁就正则改句子 |
| 收紧规则（`喜欢X` 改成必须带食物动词）导致漏抽 | 用户觉得「记不住」 | 取舍写进模块注释与报告；漏抽句式进 BACKLOG，不假装支持 |
| 阈值 0.9 放走 4 条回归 | 质量门禁变松 | 报告写实际通过率；每次改动都要求 100% |
| 方言用例本质是中文子集，覆盖有限 | 高估覆盖 | 只声称「覆盖粤语/西南官话常见句式」，不声称方言全支持 |
