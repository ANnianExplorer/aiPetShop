# S1.26 方案：修掉 CI 里那个从 S1.6 就没绿过的 docker build

日期：2026-11-14 · 批次：S1.26 · 短名：ci-docker-context · 对应 BACKLOG：C8「CI 未真正跑过」

## 目标

`agent-ci` 在 GitHub Actions 上真正跑绿。C8 的验收原话是「Actions 上 `check` 与 `image` 两个 job 绿；首次跑通后把徽章贴到 README」。

## 事实（先查再改）

| 事实 | 来源 |
|---|---|
| 从 S1.6 引入 `agent-ci.yml` 起一共 34 次运行，**34 次都是 failure** | `GET /actions/workflows/410077834/runs` |
| 每次失败的都是同一个 job：`docker build` → 步骤 `Build image` | `GET /actions/runs/{id}/jobs` |
| `lint + test + evals` 每次都是 success（本次 216 passed + 1 skipped 也在 CI 上通过） | 同上 |
| 失败原文：`ERROR: failed to build: unable to prepare context: path "backend-agent" not found` | job 日志（需带 token 才能下载） |

## 根因

workflow 顶层写了 `defaults.run.working-directory: backend-agent`，所有 `run` 步骤的 cwd 已经是 `backend-agent`；
`image` job 里又写 `docker build -t pet-agent:ci backend-agent`，构建上下文就变成了 `backend-agent/backend-agent` —— 不存在，docker 立刻退出。

这不是代码问题，也不是缺 Dockerfile（`backend-agent/Dockerfile` 一直在），纯粹是**路径写重了**，而且从来没人真的去 Actions 页看过一眼绿不绿。

## 取舍

- **A. 上下文改成 `.`（选它）**：一行改动，cwd 已经是 `backend-agent`，Dockerfile 与它 COPY 的 `requirements.txt`/`pyproject.toml`/`app` 都在这一层。
- B. 把 `working-directory` 从 workflow 级挪到 `check` job：改动更大，`pip install`/`pytest` 这些步骤都要跟着改路径，收益为零。
- C. 干脆删掉 `image` job：等于把「镜像能构建」这条护栏拆了，C8 的验收也做不到。

顺带修一件事：`on.push` 只写了 `paths`，没有 `branches`，所以**推标签也会触发一遍**——同一个提交被跑两次，白烧 runner 分钟数，也让提交在列表里多挂一个红叉。加 `branches: [main]`。

## 验收标准

1. 新提交触发的 `agent-ci`：`lint + test + evals` 与 `docker build` 两个 job 都是 success（以 API 读到的 `conclusion` 为准，不靠眼睛）。
2. 提交列表里这一条不再挂红叉。
3. 推标签不再多触发一次运行。

## 风险

| 风险 | 说明 |
|---|---|
| 本机无 docker，无法本地复现 | 只能推上去看真实运行结果；如果不行就据日志再改，不允许写「已修复」 |
| 上下文变大导致构建变慢 | `backend-agent/.dockerignore` 已存在，`.venv`/`__pycache__` 之类不会进上下文 |
| 首次跑绿后仍可能因依赖升级变红 | 与本次修复无关，属于长期维护；记录在报告的风险里 |
