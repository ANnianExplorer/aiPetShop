# S1.35 对话页无障碍基线：让状态可被听见、焦点不迷路（D9）

- 批次：S1.35
- 对应：BACKLOG D9「无障碍」——「对话页无 `aria-live`、无焦点管理」
- 状态：已完成（2026-11-20），证据见 [报告](../reports/2026-11-20-s1.35-chat-a11y.md)

## 目标

给 App 对话页补上「键盘/读屏可用」的最小完整基线，不改视觉、不改对话协议：

1. 回复生命周期可被读屏感知：发送后播报「正在回复」，`done` 后播报「回复已完成」；错误条用 `role="alert"`。
2. 消息区是带名称的可聚焦区域，流式期间 `aria-busy=true`，`done`/失败后回到 `false`，键盘用户可独立滚动。
3. 历史会话面板有真正的焦点管理：打开后焦点进入对话框、`Tab`/`Shift+Tab` 在面板内循环、`Esc` 关闭、关闭后焦点回到触发按钮；`aria-modal="true"`。
4. 输入框有可读名称并由「建议不能替代兽医诊断」描述；页面有语义标题。
5. 新文案三语同步（`zh-CN` / `en-US` / `ja-JP`）。

## 现状与证据

- `pet-lumina-app/src/views/chat/ChatView.vue:342` 消息区只有 `ref="scroller"`：没有名称、没有 `aria-busy`、不可聚焦。
- 同文件只有重连块 `role="status"`（:410）与图标按钮的 `aria-label`（:307/326/333/428/454）；流式开始/结束没有任何播报节点。
- 历史面板 `role="dialog"`（:483）但没有 `aria-modal`、打开不聚焦、`Esc` 不关闭、关闭不还焦点，背景按钮仍在 Tab 序列里。
- 错误条（:416）是普通 `div`，读屏不会主动播报。
- 页面标题是 `<p>Lumina</p>`（:318），没有 `h1`。

## 做法与取舍

- **不给消息区加 `role="log"` / `aria-live`**：流式 `delta` 每个分片都会改 DOM，读屏会逐片朗读，实际体验比不播报更糟。改用「静默消息区域（`role="region"` + `aria-busy`）+ 单独礼貌播报区（`role="status"`）只播报生命周期」两层结构；错误条本身用 `role="alert"` 承担即时播报，避免重复朗读。
- **播报文案走 i18n**：`announce()` 只接收已翻译字符串，组件不拼中文；三语键放在 `chat.a11y.*`。
- **焦点圈定在组件内实现，不引新依赖**：打开时把焦点放到 `tabindex="-1"` 的对话框容器（读屏会读 `aria-label`），`keydown` 时实时收集可聚焦元素再判断首尾，避免列表异步加载后焦点表过期。
- **不在挂载时自动聚焦输入框**：移动端会顶起软键盘，属于体验倒退；本轮只保证发送完成后焦点回到输入框（原有行为）与对话框开合的焦点闭环。
- **视觉零改动**：只加 `sr-only` 播报节点与 ARIA 属性；`sr-only` 是 Tailwind 内置工具类，无需新增样式。

## 验收标准

1. `ChatView.a11y.spec.ts` 断言：消息区有 `role="region"` + `aria-label`；发送后 `aria-busy="true"`，`done` 后为 `"false"`。
2. 同一用例断言播报区：发送后文本为「Lumina 正在回复…」，`done` 后为「回复已完成」。
3. 错误事件后，错误条 `role="alert"`，且空气泡被移除的既有行为不回归。
4. 输入框 `aria-label` 非空、`aria-describedby` 指向存在的免责说明节点。
5. 打开历史面板：`aria-modal="true"` 且 `document.activeElement` 在面板内；按 `Esc` 面板消失且焦点回到「历史会话」按钮。
6. `Tab` 在面板最后一个可聚焦元素上按下回到第一个；`Shift+Tab` 在第一个上按下回到最后一个。
7. 页面存在唯一 `h1`（Lumina）。
8. `npx vue-tsc -b`、`npx vitest run`（全量）、`npm run build` 退出码均为 0，且不新增依赖。
9. 保留原有用例全绿：`chatStream.spec.ts`、`resilientChat.spec.ts`、`MyMemory.spec.ts` 等。

## 风险

- jsdom 只能验证 DOM 焦点与属性，**不能替代真实读屏软件**（NVDA/VoiceOver）的朗读效果；报告里如实写明「未做读屏人工验收」。
- `aria-busy` 在部分读屏器上会抑制子树播报；本方案不依赖它播报，只作为状态标记，播报走独立 `role="status"` 节点。
- 历史面板内容异步加载（loading → 列表）会改变可聚焦元素集合；圈定逻辑在每次 `keydown` 时重新收集，避免焦点表过期。
- 背景内容未加 `inert`（浏览器支持参差），键盘仍可通过焦点圈定+Esc 回到页面；完整 `inert` 留作后续全站 a11y 统一处理。
- D9 原条目含「全站」含义，本轮只覆盖对话页；剩余页面登记为新的 BACKLOG 条目，不在本轮偷跑。

## 不做

- 不做全站无障碍审计与修复（设置页、我的记忆、管理端等），另立条目。
- 不动对话协议、SSE 事件、后端接口；不改视觉布局与颜色对比度。
- 不引入 `@vue-a11y` 等新依赖，不引读屏自动化工具。
- 不做 `prefers-reduced-motion` 动效降级（涉及全局样式，放到全站条目里统一处理）。
