# 执行计划：S1.7 管理端「会话工作台」（业务侧落地）

- 日期：2026-11-08
- 状态：**已完成**（2026-11-08）——后端 4 个只读接口 + 前端两页 + 测试与冒烟见 [S1.7 报告](../reports/2026-11-08-s1.7-admin.md)。计划与最终实现的差异只增加了一个接口（`/agent/admin/memory`），原因是详情页要能当场看到"记住了什么"，否则记忆错误无法在管理端定位。
- 前置：S1.6 P1 已完成（配额/事件总线/记忆/用量），见 [P1 报告](../reports/2026-11-08-s1.6-p1.md)
- 目标：让运营/客服在 `pet-lumina-web` 里**看见每一轮对话**——谁问的、模型怎么答的、调了哪些工具、引用了哪条记录、花了多少 token、记住了什么。这是"Agent 上线后要有人管"的最小闭环，也是 P1 那些接口的第一个真实消费者。

## 1. 为什么先做这个（而不是继续补基础设施）

| 现状 | 做完之后 |
| --- | --- |
| 会话数据只在 MySQL/内存里，出问题只能看日志 | 列表 + 详情页，按用户/时间/路由筛选，点进去看完整对话 |
| 用户投诉"它答错了"，我们无法复现 | 每条消息带 `run_id`，一次点击看到 5 条 step（route/llm/tool/llm）与耗时 |
| 记忆是黑盒 | 详情页直接展示该用户的 `memory_fact`，抽取错了能当场发现 |
| 成本无感知 | 列表底部汇总今日 runs / tokens / 平均延迟 |

## 2. 权限模型（先定清楚，避免"能查所有人"变成漏洞）

| 角色 | 能做什么 | 判定方式 |
| --- | --- | --- |
| 普通用户 | 只能看自己的会话（现有 `/agent/sessions/{id}/messages`） | 会话归属校验（已有） |
| 管理员 | 看全部会话、全部记忆、全局用量 | **新**：`IdentityResolver` 增加 `role`，从 Java `/auth/current` 取；`role == "admin"` 才放行 |

- 管理员接口统一前缀 `/agent/admin/`，非管理员一律 `403 forbidden`（不返回 404，因为资源存在与否不敏感，缺权限就是缺权限）；
- 管理员身份仍只从 token 换，**不接受** `x-user-id` 伪造管理员；
- 审计：管理员每次查看他人会话，打一行 `admin.access` 日志（admin_id/目标 user_id/session_id），不记录消息内容。

## 3. 接口设计（新增 3 个，均为 GET）

| 路径 | 参数 | 返回 |
| --- | --- | --- |
| `/agent/admin/sessions` | `page`(1..N) `page_size`(1..50) `user_id?` `pet_id?` `route?` `q?`(标题模糊) | `{total, page, page_size, items:[{id,user_id,pet_id,title,channel,message_count,last_route,last_active_at,status}]}` |
| `/agent/admin/sessions/{id}` | — | `{session, messages[], runs:[{id,route,intent,status,prompt_tokens,completion_tokens,latency_ms,error_code,steps[]}]}` |
| `/agent/admin/usage` | `days`(1..90) | `{days, runs, users, prompt_tokens, completion_tokens, total_tokens, avg_latency_ms, by_day:[{day,runs,tokens}]}` |

分页语义与 Java 端对齐：`page` 从 1 开始，`total` 是符合条件的总条数。

## 4. 前端（`pet-lumina-web`）

| 文件 | 职责 |
| --- | --- |
| `src/api/agent.ts` | 三个接口 + 类型（`AdminSessionItem` 等），错误走现有 `request.ts` |
| `src/views/agent/SessionList.vue` | 筛选栏（用户ID/路由/关键词）+ 表格 + 分页；行点击进详情 |
| `src/views/agent/SessionDetail.vue` | 左侧对话（user/assistant 气泡，assistant 附 citations/tools），右侧运行轨迹（steps 时间线）+ 记忆面板 |
| `src/router/index.ts` | `/agent/sessions`、`/agent/sessions/:id` |
| `src/layout/Sidebar.vue` | 新增「会话工作台」入口 |

约束：不引新依赖（Element Plus + 既有组件足够）；详情页数据一次请求取全，不做多次轮询；长列表用 `el-pagination`。

## 6. 明确不做（本轮）

- 不做"代用户发消息"（等于伪造身份，风险远大于收益）；
- 不做批量删除会话（误删不可恢复，先只读）；
- 不做权限细分（客服/运营分级）——当前只有一个 `admin` 角色，先跑通再看要不要拆；
- 不做实时刷新（列表手动刷新足够，实时推送留到有明确需求）。
