# S1.36 Agent 错误码国际化：界面文案不再直接吃服务端中文（D8）

- 批次：S1.36
- 对应：BACKLOG D8「国际化覆盖」——「Agent 错误码文案仍是中文硬编码（服务端返回 message）」
- 状态：已完成（2026-11-21），证据见 [报告](../reports/2026-11-21-s1.36-agent-error-i18n.md)

## 目标

让 App 对 Agent 的**稳定错误码**负责本地化，服务端中文 `message` 只作为日志与未知错误的兜底：

1. SSE `error` 事件：已知 `code` → 三语文案；未知 `code` → 服务端 `message`。
2. HTTP 错误（`AgentRequestError`）：`429 rate_limited` / `503 circuit_open` / `401 unauthorized` / `http_5xx` 等同样按 `code` 本地化。
3. `rate_limited` / `circuit_open` 带 `detail.retry_after_s` 时，显示「请 N 秒后再试」，而不是干巴巴的「稍后再试」。
4. 记忆页（`MyMemory.vue`）的加载 / 删除 / 导出失败同样按 `code` 本地化，不把中文原始 `message` 拼进 toast。
5. 把「`code` 是稳定契约、`message` 是中文兜底」写进 SPEC，后续新增错误码有据可依。
6. 三语键（`zh-CN` / `en-US` / `ja-JP`）同步，不改视觉布局、不改后端协议。

## 现状与证据

- `backend-agent/app/core/errors.py` 已给每个可预期错误定义稳定 `code`：`invalid_request`、`unauthorized`、`forbidden`、`not_found`、`tool_not_allowed`、`tool_failed`、`backend_error`、`model_error`、`model_not_configured`、`run_timeout`、`budget_exceeded`、`rate_limited`、`circuit_open`、`invalid_arguments`；`to_payload()` 同时下发 `code` / `message` / `retryable` / `detail`。
- SSE `error` 事件契约（`docs/spec/agent-runtime-api.md` 4.3）已包含 `{code, message, retryable, detail?}`，但没写客户端该怎么用。
- App 端两处把服务端 `message` 直接当界面文案：
  - `pet-lumina-app/src/views/chat/ChatView.vue:223`：`lastError.value = error.message`（HTTP 层）。
  - `pet-lumina-app/src/views/profile/MyMemory.vue:79`：`reasonText()` 直接返回 `Error.message`。
- SSE 层的 `applyAgentEvent()` 只把 `data.message` 塞进 `ReduceResult.error`（`pet-lumina-app/src/utils/chatStream.ts:54`），`code` 被丢掉。
- 三语 locale 里没有 `agentError.*`，所以英文/日文界面下错误条仍是中文。

## 做法与取舍

- **纯函数映射，不把 i18n 单例塞进工具层**：`agentError.ts` 只返回 `{ key, params }`，由组件调用 `t()`。这样映射表可被单测穷举，不依赖全局 locale 状态，也不破坏 `utils/` 的纯函数风格。
- **显式白名单，不自动拼 key**：`code → key` 用固定表，新增后端错误码默认走「回退服务端 message」，避免 UI 把未知错误泛化成一句没用的「出错了」，也避免漏翻时悄悄上线。
- **HTTP 层透传 `detail`**：给 `AgentRequestError` 增加只读 `detail`，`assertOk()` 解析 429/503 的 `retry_after_s`；现有构造调用不传 `detail` 时行为不变。
- **不改后端中文文案**：日志、curl、管理端仍要能读懂错误；本轮只改「App 展示层」。
- **不覆盖 Java `/api/v1` 业务错误**：`request.ts` 的错误提示属于另一条链路，D8 说的是 Agent 错误码，本轮不顺手扩张。
- **不做机器翻译 / 翻译平台**：三语文案人工写，避免机翻把宠物领域词（疫苗、驱虫、绝育）翻错。

## 验收标准

1. `agentError.spec.ts`：14 个 Agent `code` 全覆盖；`http_401/403/404/429/5xx` 映射；`retry_after_s` 插值与 `ceil`；未知 code / 空 code 返回 `null`，由调用方回退。
2. `agentError.spec.ts`：三语 locale 的 `agentError.*` 键集合完全一致（防止漏翻）。
3. `chatStream.spec.ts`：`error` 事件透出 `errorCode` 与 `retryAfterS`，原有「保留半截答案」行为不回归。
4. `ChatView.error.spec.ts`：英文 locale 下 `rate_limited` + `retry_after_s=37` 显示带 37 秒的英文文案、**不出现服务端中文**；未知 code 显示服务端原 `message`；空 message 显示通用文案；HTTP 429 同样本地化。
5. `MyMemory.spec.ts`：删除失败时按 `AgentRequestError.code` 本地化（新增 1 例）。
6. `npx vue-tsc -b`、`npx vitest run`（全量）、`npm run build` 退出码均为 0，且不新增依赖。
7. 后端零协议改动：`pytest` 全量、`ruff` 仍全绿（回归）。

## 风险

- **本地化会丢服务端细节**：例如 `not_found` 的「没有这条记忆：{key}」会被收敛成通用文案。取舍是界面不展示内部 key；原始 `message` 仍在网络层与日志里可查。报告里如实写明。
- **`retry_after_s` 四舍五入**：用 `Math.ceil` 保证「还有 0.4 秒」显示 1 秒，不会出现「请 0 秒后再试」。
- **三语翻译未经母语审校**：英文/日文按项目既有语气手写，后续可统一润色。
- **新增后端错误码会回退中文**：这是有意的安全降级，不是漏做；靠 SPEC 约束 + 映射表单测提醒维护者。

## 不做

- 不改后端 `message` 为英文，不引翻译平台或运行时翻译。
- 不覆盖管理端 `pet-lumina-web`（纯中文运营台，不在 D8 范围）。
- 不覆盖 Java `/api/v1` 业务错误（`request.ts` / `PetDetail.vue` 等）。
- 不动对话页布局、颜色、动效，不新增依赖。
