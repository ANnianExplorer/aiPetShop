## 1. 问题

B7 的后端在 2026-11-08（S1.16）就交付了 `DELETE /agent/memory/me` 与
`GET /agent/memory/me/export`，管理端也有「按用户查/删」页；但 **App 端没有任何入口**：

- 普通用户看不到 Lumina 记住了什么，只能从回答里猜；
- 想删除某条记忆只能找管理员；
- 「可查看 / 可删除 / 可携带」这三件事在用户侧是缺的——后端能力存在但没人能用，等于没交付。

BACKLOG 里这条的「剩余」一栏写的就是「前端入口」，验收写的是「删除后导出为空、下一轮不再注入」，
前半句已经由 `test_memory_api.py` 证明，缺的是让用户真的点得到。

## 2. 目标

1. 个人中心 →「我的记忆」新页面：列出长期记忆事实（label / value / 置信度 / 更新时间 / 归属范围）；
2. 范围切换：全部 / 通用（无宠物维度）/ 每只宠物，并显示各范围条数；
3. 单条删除：二次确认 → `DELETE /agent/memory/me` → 列表即时移除；
4. 导出：按范围调用 `GET /agent/memory/me/export`，合并成一个 JSON 文件下载（文件名带时间戳）；
5. 三语文案（zh-CN / en-US / ja-JP）；
6. 测试：纯函数 + 组件行为（vitest），`vue-tsc` 与 `build` 全绿。

## 3. 方案与取舍

### 3.1 为什么按范围多次请求，而不是一次拉全部

后端契约写死：`GET /agent/memory/me` 的 `pet_id` 为空表示「**不带宠物维度**的事实」，
**不是**「该用户全部事实」（`docs/spec/agent-runtime-api.md` 6.1、`backend-agent/app/api/routes.py:270`）。

想看到全部，只能对「通用 + 每只宠物」各拉一次再合并。取舍：

- 好处：完全复用既有契约，零后端改动，不碰已经绿了的契约测试；
- 代价：N+1 次请求（N = 宠物数，通常 ≤ 3）；用 `Promise.allSettled` 并发，单个范围失败不影响其它范围；
  每范围 `limit=50`（契约上限）；
- 没选「后端加 `all=true`」：本轮是前端收尾，改契约要重跑契约测试、同步两处文档，收益不匹配风险。

### 3.2 合并规则（纯函数，可测）

- 去重键 `(petId, key)`：同一范围同 key 只留 `confidence` 更高的一条（服务端理论上不会重复，客户端兜底）；
- 排序：`confidence` DESC → `update_time` DESC（null 排最后）→ `key` ASC，保证稳定；
- 置信度分档：`>= 0.85` 高 / `>= 0.70` 中 / 其余低，仅用于展示，不改数据。

### 3.3 导出为什么合并多个 scope

服务端 export 是**按范围**的（`pet_id` 语义同上，内部 `limit=200`）。客户端把各范围的
服务端导出原样装进 `scopes[]`：

```json
{
  "version": 1,
  "exported_at": "2026-11-17T14:20:00.000Z",
  "scopes": [
    { "pet_id": null, "pet_name": "通用", "facts": [] },
    { "pet_id": "5001", "pet_name": "豆豆", "facts": [] }
  ]
}
```

- 事实内容来自服务端导出接口（不受列表 50 条限制）；
- 一次点击拿到全部；`pet_name` 只为可读性，删掉不影响数据；
- 已知偏差：**这不是服务端单一文件的逐字节结果，是客户端聚合**。写进报告与页面文案，
  后续服务端提供 all 导出可无缝替换。

### 3.4 删除的即时性

`TASK_BACKEND=memory|redis` 时写入最终一致，读可能短暂看到旧值。删除成功后直接从前端列表移除、
**不自动重拉**，避免「刚删完又出现」的误判；用户重进页面时以服务端为准。

### 3.5 范围与路由

- 路由 `/my-memory`，name `myMemory`，挂在现有 profile 子路由下；
- 入口放在「系统设置」菜单（`SettingsMenu.vue`），icon `psychology`；
- 宠物列表来自 `useUserStore().pets`（路由守卫已 `init()`），页面不额外拉接口。

## 5. 风险

- **N+1 请求放大**：宠物多时请求数线性增长；当前 `limit=50`/范围，暂可接受，宠物 >5 再考虑后端聚合接口（写回 BACKLOG）。
- **导出格式是客户端聚合**：与服务端单范围文件不同，已在报告和页面文案说明。
- **jsdom 没有 `URL.createObjectURL`**：下载封装抽到 `utils/download.ts`，组件测试 mock 掉；
  真实浏览器行为本轮无浏览器可点，只能靠类型检查 + 构建 + 单测，报告如实写「未做真机点击」。
- **最终一致**：删除后立即刷新列表可能看到旧值，页面文案提示「重新进入以服务端为准」。

## 6. 不做

- 编辑记忆、按 key 搜索、分页（服务端上限 50/200）；
- 后端接口改动、管理端改动；
- 浏览器 e2e（Playwright，属 BACKLOG C9）。
