## 1. B4：失败不是立刻重投，也不是立刻进死信

现状问题：`nack` 直接把消息 `LPUSH` 回主队列，失败一次就立刻重试一次——下游短暂抖动会变成热循环；而且"进死信"只有人工重放一条路。

设计（与 SQS 语义对齐）：

| 环节 | 做法 |
| --- | --- |
| 失败重试 | `nack` 写入 `{prefix}:{topic}:retry`（ZSET，score = now + backoff(attempt)），**不再立刻回主队列** |
| 退避 | `backoff = min(base * 2^(attempt-1), cap)`，默认 `base=5s`、`cap=600s` |
| 到期搬回 | 巡检器每 tick 调 `retry_due(topics)`，把 score ≤ now 的搬回主队列（`attempt` 已 +1） |
| 次数耗尽 | `attempt >= max_attempts` 进死信，日志 `task dead letter` |
| 死信自动重试 | **默认关闭**；开启后按 `dlq_redrive_interval_s` 周期把死信放回（`attempt=1`、`redrives+1`），`redrives >= max_redrives` 后留在死信等人工 |
| 为什么默认关 | 死信往往意味着代码/数据问题，自动重试只会刷日志；默认人工看，需要时再开 |

不变量：自动重试是**有界**的（attempt 与 redrives 双上限），任何路径都不会无限重投。

## 2. B2：多副本到底串不串

验收方式：本机起两个 agent 副本（8099/8100），共用一个 MySQL 与 Redis，验证：

1. **任务不重复消费**：同一批 `agent.memory.observe` 只被一个副本处理（`BRPOPLPUSH` 的原子性）；
2. **会话/事件跨副本可见**：A 上发消息，B 上 `GET /agent/runs/{id}/events` 能续传（事件在 Redis）；
3. **限流共享**：`RATE_LIMIT_BACKEND=redis` 下，A 打满 20 次后 B 也返回 429；
4. **幂等跨副本**：同一 `client_message_id` 在 A、B 各发一次，只产生一个 run（唯一键在 MySQL）；
5. **熔断是单实例状态**（明确记录为已知限制，不做跨副本共享）。

产出：`scripts/multi_replica_smoke.py`（对两个 base URL 跑上述五项）+ REPORT 一节。

## 3. 桌宠档 A（C6）

范围：App 内 H5 桌宠，**不依赖美术资源**（用 SVG + CSS 动画画出来），先证明"状态机 + 数据驱动"成立，后续换 Live2D 只替换渲染层。

| 关注点 | 做法 |
| --- | --- |
| 状态来源 | `derivePetMood({healthScore, todaySteps, dueReminders, hour, riskCount})` 纯函数 → `idle/happy/hungry/sleepy/worried/playing` + `reason` |
| 渲染 | `DesktopPet.vue`：固定右下角、可拖拽、可关闭；SVG 身体 + CSS 动画（呼吸/眨眼/摇尾/抖动） |
| 文案 | 每个状态一组短句（i18n），同状态 30 分钟内不重复；深夜（0–6 点）静音 |
| 交互 | 点一下切 `playing` 并出气泡；长按出现「藏起来/换只宠物」菜单 |
| 数据真实 | 只用已加载的 `petHealthData`/`tasks`/`profile`，不造假数据；没数据就是 `idle` |
| 无障碍 | 尊重 `prefers-reduced-motion`；不遮挡底部导航与输入区；可一键关闭并记住 |
| 测试 | `vim` 不适用——用 vitest 测 `derivePetMood` 与"文案不重复"的纯逻辑 |
