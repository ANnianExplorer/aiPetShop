# S1.28 系统提示词版本化：让每条回答都能对上「用的是哪一版」（BACKLOG D6）

- 状态：已完成
- 日期：2026-11-15
- 对应条目：BACKLOG D6「提示词没有版本管理」
- 预算：单轮夜间维护剩余时间（约 45 分钟）

## 1. 问题

`SYSTEM_PROMPT` 原来是一段写死在 `app/graph/nodes.py:23-30` 的字符串字面量。带来的实际麻烦：

- **不可追溯**：线上回答风格/引用习惯变了，日志里只有 `model` 名，没有「提示词是哪一版」，无从对账；
- **改动无痕迹**：改一个字，git 里就是一行 diff，没人会为它写变更记录；回滚时也不知道「上一版」长什么样；
- **无法灰度**：将来想把新版提示词按用户/渠道切流，连一个版本标识都没有。

这条不是「想要更优雅」，是排查成本：宠物健康场景里，提示词第 2 条（医疗判断必须标注「仅供参考」）
一旦被谁顺手改掉，出了事故连「当时用的哪版」都答不上来。

## 2. 目标

1. 提示词正文集中到 `app/graph/prompts.py`，以 `版本号 → 正文` 的登记表形式存在，**只增不改**；
2. 每个版本配一条**手写冻结的 sha256**，改正文不升版本 → 单测红（CI 拦）；
3. 每轮 run 的 assistant 消息 `meta` 与 `run finished` 日志都带上 `prompt_version`；
4. 安全底线（「不替代兽医诊断」「必须先调用工具」「不知道就说不知道」）被删时测试红一次；
5. 纯离线、零依赖、不改任何 HTTP 契约与 SSE 事件形状。

## 3. 方案与取舍

### 3.1 结构

```
app/graph/prompts.py
  PROMPT_VERSIONS: dict[str, str]   # "2026-11-15.1" -> 正文（只增）
  FROZEN_SHA256:   dict[str, str]   # "2026-11-15.1" -> 手写哈希（闸门）
  PROMPT_VERSION = 登记表最后一个键
  SYSTEM_PROMPT  = PROMPT_VERSIONS[PROMPT_VERSION]
  PROMPT_SHA256  = sha256(SYSTEM_PROMPT)
```

`nodes.py` 改成 `from .prompts import SYSTEM_PROMPT`，模块级名字不变（`nodes.SYSTEM_PROMPT` 仍可用），
`app/graph/__init__.py` 增加导出 `PROMPT_VERSION` / `PROMPT_SHA256`，调用方不用改 import。

### 3.2 闸门为什么用「冻结常量」而不是「运行时重算」

如果哈希在运行时由正文算出，那它永远等于自己，等于没有校验。`FROZEN_SHA256` 是**手写常量**，
改正文就必须同时改这里；测试遍历 `PROMPT_VERSIONS`，要求 `sha256(正文) == FROZEN_SHA256[版本]`。
想原地改历史版本 → 红；想新增版本 → 必须同时登记正文与哈希，git diff 里一眼可见。

**已知局限（写清，不装）**：同一个人可以在同一个提交里改正文 + 改冻结哈希 + 不升版本号，
测试拦不住「明知道要升版本却故意不升」。它拦的是**无意改动**（复制粘贴、格式化、顺手润色），
以及让每次改动都在 diff 里显形。真正的审批要等 CI 之外的 code review。

### 3.3 为什么只进 meta 和日志，不改 SSE

`DONE` 事件是客户端契约（`docs/spec/agent-runtime-api.md`），加字段意味着 App、管理后台、
断线重连回放都要跟着改，收益与风险不成比例。`meta` 是 JSON blob、管理端详情页已经透传，
日志是运维面，两个地方够定位。等真要灰度切流时再升 `DONE` 事件。

### 3.4 版本号为什么用日期

`2026-11-15.1` 一眼能对上是哪天改的、当天第几版；`.` 后缀避免同日多次改动冲突。
排序即时间序，取「最后一个键 = 当前版本」不需要额外字段。

### 3.5 拒绝的选项

- **提示词放数据库 / 配置中心**：本项目 agent 侧零外部依赖优先，且这会引入「配置漂移」新问题；先有版本号，再说动态加载。
- **每轮把完整正文写进日志**：违反 ADR-0007（日志不落内容）且体积大；只记版本号 + 哈希。

## 5. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 只拦「无意改动」，拦不住「故意不升版本」 | 版本记录可能被人为绕过 | 局限写进模块注释与本文件；靠 review + 每次改动在 diff 里显形 |
| 安全措辞测试按字面匹配 | 未来合理改写会被迫改测试 | 这是有意为之：改安全底线就该让人看一眼；测试注释写明了 |
| `meta` 新增字段 | 依赖 `meta` 严格结构的老客户端可能惊讶 | `meta` 一直是开放 JSON；管理端按 key 取值，不校验集合 |
| 版本号随日期变，跨天改动要人记得改 | 忘改 → 测试红（`PROMPT_VERSION` 无新键） | 红即提示；错误信息里直接写了怎么改 |
