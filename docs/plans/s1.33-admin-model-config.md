# S1.33 管理员统一模型配置（用户需求）

- 批次：S1.33
- 对应：用户需求「管理员统一配置模型」，BACKLOG C10
- 状态：已完成（证据见 `docs/reports/2026-11-18-s1.33-admin-model-config.md`）

## 目标

把模型配置从「只能改部署环境变量」变成管理端可操作的能力：

1. 管理员在「模型配置」页填写 provider / base_url / model / API Key，可测试连接、保存并立即生效。
2. Key 只写不读：接口不回传明文或密文，页面只显示末 4 位掩码。
3. 保存前先用新配置构建模型；构建失败不落库、不切换运行时。
4. 数据库没有启用配置、或配置被禁用时，回退到部署级 `PET_AGENT_LLM_*` 环境变量。
5. 热切换只影响新请求；在途 run 继续使用启动时的模型与图。

## 做法与取舍

- **配置归属 Agent 服务**：模型是 Agent 的运行资源，管理端只作为操作入口；接口挂在 `backend-agent` 的 `/agent/admin/model-config`，复用现有 `satoken` 与管理员校验。
- **单条当前配置**：表 `agent_model_config` 固定 `id=1`，避免多行「默认配置」带来的歧义；需要多套配置时再加版本/分组。
- **加密不引依赖**：本机 venv 没有 `cryptography`，且离线安装失败，因此用 stdlib 实现 HMAC-SHA256-CTR 密钥流 + HMAC-SHA256 Encrypt-then-MAC；格式带 `v1:` 版本前缀，主密钥来自 `PET_AGENT_CONFIG_SECRET` 或自动生成的 `data/model-config.key`（0600）。生产建议换 KMS/Vault/Fernet。
- **存储双实现**：memory 模式写 `data/model-config.json`（原子替换），mysql 模式写 `agent_model_config`；两者同一 `ModelConfigStore` 接口。
- **热切换**：`ModelConfigService` 构建新模型后回调 `create_app.apply_runtime_model` 重建 graph，再 `AgentRunner.reconfigure`；旧模型延迟到 shutdown 关闭。
- **页面只做管理端**：新增 `pet-lumina-web/src/views/agent/ModelConfig.vue`，不把 Key 暴露给 App；App 继续只消费对话接口。
- **测试选择器**：页面按钮加 `data-testid`，为后续浏览器 e2e 留入口；本轮没有把模型配置用例塞进现有 e2e（8080 被用户 Java 后端占用，不误杀）。

## 验收标准

1. 非管理员访问 `GET/PUT/POST /agent/admin/model-config*` 返回 403；管理员可读、可保存、可测试连接。
2. 保存后 `GET` 返回 `source=db`、`has_api_key=true`、`api_key_masked` 只含末 4 位；响应与页面均无明文 Key。
3. 保存成功立即生效：新请求的 `run.model` 使用新模型名；禁用后回退 env（有 env key 时）或 `none`（无 env key 时）。
4. 空 Key 保存沿用旧 Key；启用但无任何 Key 时返回 400；测试连接缺 Key 时返回 400。
5. 配置构建失败时不落库、不切换运行时，管理端返回可读错误。
6. memory 模式落盘文件只含 `api_key_cipher` 密文，不含明文；密文被篡改时解密失败。
7. `pytest` 全量通过（新增 9 例模型配置测试）；`ruff check` 通过。
8. 管理端 `vue-tsc -b` 与 `npm run build` 通过；页面在管理端路由/侧栏可进入。
9. 未配置/禁用时 `/readyz` 按运行时模型状态返回 503，不把注入的测试模型误判为生产就绪。

## 风险

- 自定义加密是过渡方案，缺少密钥轮换与 KMS 审计；主密钥文件丢失会导致已保存 Key 不可恢复。
- `base_url` 由管理员填写，理论上可指向内网地址（SSRF 面）；当前依赖管理员可信，后续可加域名白名单/私网地址拦截。
- MySQL 存储与 DDL 未在真机 DSN 下执行；本轮只验证 memory 文件存储与接口契约。
- 管理端页面只做了 `vue-tsc`/build，未做浏览器点击；8080 被用户 Java 后端占用，e2e 栈无法启动，未强行停用户进程。
- 热切换对在途 run 的隔离依赖 `AgentRunner` 在 run 开始时固定 model/graph；已加注释与局部变量，但没有专门的并发时序测试。

## 不做

- 不做每用户 BYOK、配额、计费与滥用防控（方案 B，另立需求）。
- 不做多模型路由、灰度、按用户/渠道切流。
- 不引第三方加密库，不改 App 端模型配置入口。
- 不把模型配置 e2e 强行接入现有 Playwright 套件；等 8080 空闲后补一条管理端用例。
