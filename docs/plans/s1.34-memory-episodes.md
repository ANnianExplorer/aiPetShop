# S1.34 情景记忆：从「发生过的事」到可召回片段（C1 第一刀）

- 批次：S1.34
- 对应：BACKLOG C1「情景记忆 `memory_episode`」
- 状态：已完成（证据见 `docs/reports/2026-11-19-s1.34-memory-episodes.md`）

## 目标

把只建了表、从未写入的 `memory_episode` 接成一条完整链路：

1. 用户说「上周给豆豆洗澡了」时，写入一条情景：`kind=bath`、`occurred_at=2026-11-12 00:00:00`、`summary=原话`、`source_message_id=该条用户消息 id`。
2. 下一轮问「上次洗澡是什么时候」时，召回这条往事，注入 system prompt，带日期与来源消息 id。
3. 用户可列出、删除、导出自己的情景记忆；跨用户/跨宠物物理隔离。
4. 任务队列至少一次投递不会产生重复情景（按 `(user_id, source_message_id)` 幂等）。

## 做法与取舍

- **不引向量库，先做确定性召回**：C1 原方案依赖 pgvector，本机没有可用向量服务，本轮用「近 200 条情景 + 规则打分」：0.55×事件类型命中 + 0.35×中文字符重叠 + 0.10×90 天新鲜度，阈值 0.50（事件类型必须命中），最多注入 3 条。能覆盖「上次洗澡/上周呕吐」这类明确指向，但语义改写（「洗香香」）召回不了；这是本轮明确接受的上限，向量检索仍留在 BACKLOG。
- **抽取规则与事实记忆同风格**：问句、否定句、习惯句不抽；一条消息最多一个情景；时间只精确到日（`00:00:00`）。相对时间「上周=-7 天、上个月=-30 天」是近似值，摘要保留原话，模型看到的是原话 + 推算日期。
- **`source_message_id` 写进表**：C1 验收要求「带原消息 id」。新增列 + `UNIQUE (user_id, source_message_id)`，让旁路队列重复消费天然幂等；`source_message_id` 为 NULL 的手工数据不受唯一键约束。
- **复用现有接线**：情景读写都挂在 `MemoryService` 上，`AgentRunner` 与任务消费者只多调两个方法，`create_app` 的装配不变；召回失败/写入失败都吞异常，不影响对话主链路。
- **导出升 v2**：`GET /agent/memory/me/export` 增加 `episodes` 字段并升版本号；v1 消费者忽略新字段即可，不需要导入器改动。
- **MySQL 迁移单独一支**：`backend/sql/v2.19-agent-episode.sql` 给既有表加列/索引。MySQL 不支持 `ADD COLUMN IF NOT EXISTS`，脚本头注明只执行一次。

## 验收标准

1. `extract_episode("上周给豆豆洗澡了", now=2026-11-19)` 返回 `kind=bath`、`occurred_at=2026-11-12 00:00:00`、`summary` 保留原话。
2. 问句（「上次洗澡是什么时候？」）、否定（「今天没洗澡」）、习惯（「它洗澡特别乖」）不产出情景；无时间词但带完成标记（「刚给豆豆洗了澡」）按今天记录。
3. 同一条用户消息重复写两次，只产生一行情景（`source_message_id` 幂等）；不同用户/宠物互不可见。
4. 两轮对话：第一轮写入情景，其 `source_message_id` 等于该轮 user message id；第二轮「上次洗澡是什么时候」的 system prompt 含日期、事件类型、来源消息 id。
5. `GET /agent/memory/me/episodes`、`DELETE /agent/memory/me/episodes/{id}`、`GET /agent/memory/me/export` 隔离与 401 行为与现有事实接口一致；导出 `version=2` 且含 `episodes`。
6. 仓储契约测试同时覆盖 memory 与 MySQL（有 `PET_AGENT_TEST_MYSQL_DSN` 时）。
7. `pytest` 全量通过、`ruff check` 通过；未跑 MySQL 变体时报告写清「未开 DSN」。

## 风险

- 规则召回的召回率有限：明确事件词可靠，语义改写/代词指代（「那次洗香香」）会漏；不引入向量库就无法根治。
- 相对时间近似：上周按 -7 天、上个月按 -30 天，跨月边界会差 1–3 天；摘要保留原话作为补偿。
- 一条消息只抽一个情景：一句话说两件事时只记第一件（按 `EPISODE_KINDS` 顺序）。
- `UNIQUE (user_id, source_message_id)` 把「一条消息最多一个情景」写进 schema；将来支持多情景需要改成 `(user_id, source_message_id, kind)`。
- MySQL DDL 与契约变体依赖本机 DSN；本机不一定有可用 MySQL，报告会如实写明。

## 不做

- 不引 pgvector / 外部向量库，不做 embedding 写入与 ANN 检索。
- 不做情景编辑、合并、批量删除、按时间范围查询。
- 不做历史消息回填：只从本轮上线后的新消息开始积累。
- 不改 App「我的记忆」页面；导出 JSON 自动多出 `episodes` 字段，页面无需改动。
- 不做多情景/多事件抽取，不改事实记忆抽取规则。
