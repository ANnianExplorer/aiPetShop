### P1 可靠性（本轮执行）

| 项 | 为什么 | 验收 | 状态 |
| --- | --- | --- | --- |
| 每用户配额（次数 + token 预算） | 现在任一账号可无上限消耗 LLM | 超限返回 `rate_limited` + `Retry-After`，响应头带剩余次数 | ✅ 已完成 |
| 单次 run token 预算 | 一次对话就能烧穿日额度 | 超 `run_token_budget` 抛 `budget_exceeded` | ✅ 已完成 |
| 事件总线 | 进程内缓冲多副本失效 | Redis Stream（`event_backend=redis`）续传，跨进程可见 | ✅ 已完成 |
| 长期记忆 | 每轮都从零开始，问不出"它上次…" | `memory_fact` 两表 + 抽取算子 + 召回注入 system | ✅ 已完成 |
| 用量聚合 | 不知道钱花在哪 | `GET /agent/usage/me` 按账号 × 天数聚合 | ✅ 已完成 |
| 幂等键 | 客户端重试会重复计费 | `Idempotency-Key` 相同 → 复用首次 run 结果 | ⏳ 挪到 P2 |
| 熔断与超时 | Java 挂了会让工具 30s 挂住 | 连续 N 次失败后快速失败，恢复自动半开 | ⏳ 挪到 P2 |

P1 的取舍说明：

- **限流与 token 预算拆成两层**：配额（次数）挡刷量，预算（token）挡单次长对话；只做一层都会被绕过。
- **Redis 选项默认关闭**（`event_backend=memory` / `rate_limit_backend=memory`）：单机开发不引入 Redis 依赖，但生产切两个环境变量即可，不改代码。
- **记忆只从对话里抽"低风险事实"**（名字/年龄/体重/过敏/忌口/爱吃/疫苗），抽取失败或低置信度就丢弃，宁可少记不可记错。

### P2 可观测与成本（P1 之后）

- 每次 run 落 `prompt/completion tokens`、`latency`、`tool 次数`、`模型名`（已有字段，缺聚合与上报）；
- 指标导出（Prometheus 文本格式）：`agent_run_total{route,status}`、`agent_latency_seconds`、`llm_tokens_total`；
- 链路：`request_id → run_id → tool_call_id` 三段可串；
- 成本看板口径：按 `user_id × day` 聚合，先出 SQL 再上图。

### P3 记忆扩展与数据治理（P2 之后）

- `memory_episode` 接向量检索（pgvector），只在"还记得上次那件事吗"类问题里用；
- MySQL 迁移工具（Alembic 或自建 `migrations/` 版本表），禁止手改 DDL；
- 真实模型 + 真实 Java 的回归基线（金标集：20 条跨会话记忆用例）。

## 3. 风险与取舍

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 本机无 docker | 镜像未实际构建 | 明确标注"未验证"，CI 里加 build 步骤 |
| 无 JDK/MySQL | 真后端与真库未联调 | 桩 + 契约测试；`PET_AGENT_TEST_MYSQL_DSN` 可把契约测试切到真库 |
| ruff 首次接入改动面大 | 可能触碰业务代码 | 先 `--fix` 机械项，人工复核 diff；不引入与业务无关的风格争论 |
| 日志含用户内容 | 隐私风险 | 只记 id/长度/耗时，不记 message 原文 |
| 记忆抽错（把"不吃肝脏"记成爱吃） | 错误事实会进 system 提示 | 规则只认明确句式 + 置信度阈值 + `GET /agent/memory/me` 可人工核对 |
| 限流误伤（多副本内存计数各算各的） | 同一用户可用量翻倍 | 生产切 `rate_limit_backend=redis`；内存实现标明只适合单副本 |
