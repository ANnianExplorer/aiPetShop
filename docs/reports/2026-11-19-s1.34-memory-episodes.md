## 2. 做了什么

### 2.1 表结构（迁移，不自动执行）

新增 `backend/sql/v2.19-agent-episode.sql`：

- `memory_episode` 增 `kind VARCHAR(32) NOT NULL DEFAULT ''`、`source_message_id BIGINT NULL`；
- 唯一键 `uk_source_message (user_id, source_message_id)`：同一用户同一条来源消息只写一行；
- 索引 `idx_user_kind (user_id, pet_id, kind)`：召回按用户/宠物/类型过滤。

MySQL 8 不支持 `ADD COLUMN IF NOT EXISTS`，脚本头注写明**只执行一次**。本机未连真机 MySQL，DDL 未实际执行。

### 2.2 抽取与召回（`app/memory/episodes.py`）

- 10 类事件：洗澡 / 驱虫 / 疫苗 / 体检 / 就医 / 绝育 / 美容 / 剪指甲 / 呕吐 / 腹泻。
- 时间词：今天、昨天、前天、大前天、刚才、刚刚、上上周、上周、上个月、上上个月、半个月前、N 天前、N 周前、N 个月前；`occurred_at` 归一到自然日 `YYYY-MM-DD 00:00:00`。
- 不写入：问句（`?/？/吗/什么/哪/怎么/多少/是否/多久`）、否定（`没/未/不用/不要/不需要/还没`）、没有时间词且没有完成标记（`了/过/刚/已经`）的习惯句。
- 召回打分：`0.55 × 事件类型命中 + 0.35 × 中文字符重叠 + 0.10 × 90 天新鲜度`；阈值 `0.50`，事件类型必须命中，最多 3 条。
- 注入格式：`- 2026-11-12（洗澡）：上周给豆豆洗澡了（来源消息 1794...）`。

### 2.3 运行时与 API

- `MemoryService.record_episode(...)`：抽取失败返回 `None`，不阻塞对话；`episode_lines(...)` 异常降级为空。
- `AgentRunner` 在写入用户消息后、构图前召回；state 增加 `episode_lines`；assistant message 的 `meta` 增加 `memory_episodes`；`_observe` 把 `session_id/message_id/run_id` 带进队列 payload。
- 任务消费者在事实写入后调用 `record_episode`，按 `(user_id, source_message_id)` 幂等。
- `prepare_node` 在事实块、画像块之后注入「与这次问题相关的往事」；L1/L2 都生效。
- 新增 `GET /agent/memory/me/episodes`、`DELETE /agent/memory/me/episodes/{episode_id}`；导出升 `version=2` 并增加 `episodes`（v1 消费方可忽略新字段）。
- 内存与 MySQL 仓储都实现 `add/list/delete_memory_episode`；MySQL 用唯一键 + 回查处理重复投递。

### 2.4 测试

- 新增 `tests/test_memory_episodes.py`：抽取、相对日期、问句/否定/习惯不写、幂等、召回只命中类型、用户/宠物隔离、格式化。
- `tests/test_memory_api.py`：导出 v2、列表、删除、重复删除 404、跨用户隔离、401。
- `tests/test_repository_contract.py`：来源消息幂等、隔离与删除、无来源消息不去重。
- `tests/test_api.py`：两轮对话集成，第一轮写入并断言 `source_message_id == user_message.id`，第二轮 system 含日期、原话与来源消息 id。
- `tests/test_task_queue.py`：同一条观察重复投递只写一条情景。

## 4. 已知缺口与风险

1. **MySQL 未真机验证**：迁移脚本、唯一键冲突回查、`detail JSON` 读写只经过内存契约测试；上线前需在 MySQL 8 执行 `v2.19-agent-episode.sql` 并跑带 `PET_AGENT_TEST_MYSQL_DSN` 的契约测试。
2. **召回是词面规则，不是语义召回**：事件类型必须命中，改写说法（如「冲凉」）召回不到；同义词典、向量召回留给 S2（pgvector 选型）。
3. **相对时间只精确到日**：上周固定 -7 天、上个月固定 -30 天，跨月边界会有一两天误差；`occurred_at` 不存具体时刻。
4. **一条消息最多一个情景**：同句「洗澡又驱虫」只取优先级最高的一个；多事件拆分未做。
5. **唯一键依赖 `source_message_id` 非空**：无来源消息的行不去重（当前写入路径都会带来源消息）。
6. **结构化回填未做**：日志/健康表写入时自动生成情景（架构文档里的更可靠路径）尚未接入，当前只有对话抽取。
7. **未做浏览器点击**：本轮只跑后端；App 未改，无需前端构建。
