## 2. 关键设计（为什么这样能拦住「悄悄改提示词」）

- 哈希**不是运行时重算**的：`FROZEN_SHA256` 是手写常量，测试要求 `sha256(正文) == FROZEN_SHA256[版本]`；
  如果哈希由正文现算，它永远等于自己，等于没校验。
- 当前版本 = 登记表**最后一个键**，所以新增版本不用改任何别的地方；想原地改旧版本则必须同时改冻结哈希，git diff 里一眼可见。
- 已知局限（不装）：同一个人可以在一个提交里同时改正文 + 哈希且不升版本号，测试拦不住「故意绕过」；它拦的是复制粘贴/格式化/顺手润色这类**无意改动**，以及让每次改动显形。

## 6. 风险与遗留

1. **只能拦无意改动**：见 §2 的局限。真正的审批还得靠 review。
2. **`meta` 目前没有 HTTP 出口**：`prompt_version` 已落库（`agent_message.meta`）与日志，但管理端会话详情接口不返回 message meta，界面上暂时看不到。要展示得另开一刀（改 admin 响应 + 前端），已写进 BACKLOG D6 的剩余项。
3. **安全措辞测试按字面匹配**：后续合理改写会先红一次，需要人手工改测试——这是有意的，安全底线改动应该让人看一眼。
4. **版本号靠人写日期**：跨天改动忘改 → 测试红，错误信息里写了怎么改；没有自动化。
5. **环境坑**（本轮又踩一次）：PowerShell `Get-Content -Raw` 读 UTF-8 中文文件再写回会按本地代码页解码，产生乱码；改文件一律用 `write` / `edit` 工具或 `python -X utf8`，不要用 `Get-Content | Set-Content` 管道。
