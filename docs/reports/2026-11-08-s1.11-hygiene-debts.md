## 1. E1：验证码硬编码 `123456`

**修改前**：`backend/src/main/java/com/petlumina/backend/controller/user/AuthController.java:138` 直接 `String code = "123456";`，任何人拿到手机号就能注册/重置密码。

**修改后**

| 文件 | 改动 |
|---|---|
| `backend/src/main/java/com/petlumina/backend/utils/VerifyCodeUtils.java`（新增） | `generate(fixedCode)`：配置非空返回配置值，否则 `SecureRandom` 生成 6 位数字；`randomDigits(n)` 长度非法抛 `IllegalArgumentException` |
| `backend/src/main/java/com/petlumina/backend/controller/user/AuthController.java` | 加 `@Value("${petlumina.auth.fixed-verify-code:}") private String fixedVerifyCode;`；`sendCode` 改为 `String code = VerifyCodeUtils.generate(fixedVerifyCode);` |
| `backend/src/main/resources/application-dev.yml` | 新增 `petlumina.auth.fixed-verify-code: "123456"`，注释写明"仅本地开发/自动化测试；生产不要配置，留空即随机" |
| `backend/src/test/java/com/petlumina/backend/utils/VerifyCodeUtilsTest.java`（新增） | 5 条：固定码原样返回并裁空白、未配置时 6 位纯数字、1000 次生成至少 900 个不同值、指定位数、非法位数报错 |

**为什么不是"删掉硬编码就完事"**：App 的注册/重置流程要收到验证码，本项目没接短信网关，直接改随机会让本地流程不可用。所以做的是"默认安全（随机）+ 显式配置降级（dev 固定）"，并且降级点写进配置文件和测试。

**证据**

```

[INFO] BUILD SUCCESS
```

## 2. E3：管理端类型检查形同虚设

**问题**：`pet-lumina-web/tsconfig.json` 是 `"files": []` + references，`build` 脚本却是 `vue-tsc --noEmit` —— 解析到根 tsconfig 后一个文件都没检查。显式 `vue-tsc -p tsconfig.app.json` 能报出 8 个错误。

**修改后**

| 文件 | 改动 |
|---|---|
| `pet-lumina-web/package.json` | `build: vue-tsc -b && vite build`；新增 `typecheck: vue-tsc -b`；新增 devDependency `@types/node` |
| `pet-lumina-web/tsconfig.node.json` | `compilerOptions.types = ["node"]`（修 `vite.config.ts` 的 `Cannot find module 'path'` / `Cannot find name '__dirname'`） |
| `pet-lumina-web/src/types/index.ts` | `Pet` 补 `feedingCount?` / `feedingTotal?` / `notes?`（与后端 `PetVO` 对齐） |
| `pet-lumina-web/src/views/content/PostDetail.vue` | `imageList`/`tagList` 改为直读 `postData.value?.imageList ?? []` 与 `(postData.value?.tagList ?? []).filter(t => !t.startsWith('topic:'))` |

**顺带挖出的真 bug**：`PostDetail.vue` 旧代码读 `postData.images` 再 `JSON.parse`。而后端 `PostVO` 返回的是 `List<String> imageList` / `tagList` —— 字段根本不存在，`JSON.parse(undefined)` 必抛、被 `catch` 吞掉，**管理端帖子详情里的图片和标签一直是空的**。这是类型检查被关掉之后藏住的运行时缺陷，不是"类型洁癖"。

**证据（门禁不是空转）**

```
# 故意注入类型错误
src/__typecheck_probe.ts(1,7): error TS2322: Type 'string' is not assignable to type 'number'.
PROBE_EXIT=2
# 删掉探针
CLEAN_EXIT=0
```

## 4. E5：今日提醒 `includes('今天')`

**修改前**：`pet-lumina-app/src/views/schedule/ScheduleList.vue:37` 用 `r.remindTime.includes('今天')` —— 后端存的是 `yyyy-MM-dd HH:mm:ss`，永远不含"今天"，今日列表恒空；`week` 分支其实只过滤了未完成。

**修改后**

| 文件 | 改动 |
|---|---|
| `pet-lumina-app/src/utils/schedule.ts`（新增） | `parseRemindTime`（空/垃圾值 → null，空格分隔转 `T`）、`isSameLocalDay`、`isToday(value, now)`、`isWithinNextDays(value, days, now)`（左闭右开） |
| `pet-lumina-app/src/views/schedule/ScheduleList.vue` | `today` → `isToday(r.remindTime)`；`week` → `r.isCompleted === 0 && isWithinNextDays(r.remindTime, 7)` |

**证据**：`pet-lumina-app/src/utils/schedule.spec.ts` 9 条，其中一条直接钉住原缺陷：

```ts
expect('2026-11-07 09:30:00'.includes('今天')).toBe(false)   // 旧实现为什么永远为空
expect(isToday('2026-11-07 09:30:00', NOW)).toBe(true)        // 新实现
```

## 6. 已知缺口

1. **E1 没有接短信网关**：生产环境必须不配置 `petlumina.auth.fixed-verify-code`，否则仍是固定码；配置项本身需要部署侧纪律，代码里没做"prod profile 禁止固定码"的强校验。
2. **E3 只覆盖管理端**：`pet-lumina-app` 一直是 `vue-tsc -b`，本轮没动；但 App 里 41 处 `as any`（E11）仍在，类型安全仍打折。
3. **E4 的 `category` 写入路径未审**：历史数据里如果存的是中文标签，靠 `LEGACY_LABELS` 兜底；新建帖子写的是什么值应由 `CreatePost.vue` 决定，本轮未改动写入侧。
4. **没有浏览器回归**：本轮 E4/E5 用单测钉行为，未重新开 Edge 点一遍；下一轮做 E2/E6/E7 时可以顺手补一次端到端。
