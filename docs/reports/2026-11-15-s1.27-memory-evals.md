# S1.27 记忆抽取评测（BACKLOG C3）

- 日期：2026-11-15
- 方案：[plans/s1.27-memory-evals.md](../plans/s1.27-memory-evals.md)
- 范围：`backend-agent`（`evals/` 用例与套件、`app/memory/extract.py` 抽取规则、`tests/test_memory.py`）
- 结论：`memory` 套件从 2 条做到 48 条，阈值从 1.0 改为 0.9；先用用例量出 5 类真实抽取缺陷，再修规则，**48/48 = 100%**。`pytest` 222 例 0 失败 1 跳过，`ruff` 全绿，`evals` 全量 EXIT=0。

## 1. 为什么做这条

`BACKLOG` 的 C3 写的是「`evals` 里 `memory` 只有 2 条用例、阈值 1.0」。原来的 `run_memory` 只验证「落库条数 = 轮数 × 2」，也就是说：

- 抽出来的值对不对（`allergy=花生` 还是 `花生有点`）完全不管；
- 否定句（「它对鸡肉不过敏」）抽出假事实也不管，因为条数照样对；
- 阈值 1.0 在 2 条用例上等于没有统计学意义。

这条是 P2 里唯一不依赖外部服务（没有 pgvector、没有 RocketMQ、没有 Docker）且能量化收益的事项，所以本轮选它。

## 2. 改了什么

### 2.1 评测侧（先有尺子，再改代码）

`backend-agent/evals/run.py`：

- `THRESHOLDS["memory"] = 0.9`（原 1.0）。0.9 在 48 条上允许最多 4 条回归（44/48 仍绿），既能挡住退化，又不会因为一条方言用例误报而全红。
- `run_memory` 改成按用例形状分派到三个子套件：
  - `text` → `run_extract`：`extract(text)` 抽出的事实**集合全等**（多抽一个 key 也算失败），可带 `forbid` 列出「绝不能出现的 key」；
  - `observe` → `run_observe`：真跑 `MemoryService(repo, min_confidence=…).observe()`，把 `pet_id → {key: value}` 与期望全等，可再校验 ADD/UPDATE 的 `ops` 序列；
  - `turns` → `run_history`：保留原来「多轮落库」的语义。
- 失败 note 区分 `wrong` / `extra` / `forbid_leaked`，让下一轮直接看出是漏抽还是多抽。

`backend-agent/evals/cases.jsonl`：新增 46 条 memory 用例（memory 合计 48 条），分四组：

| 组 | 条数 | 覆盖 |
| --- | --- | --- |
| `mem-ext-*` | 28 | 名字/年龄/体重/过敏/忌口/爱吃/疫苗，含「它特别喜欢吃鸡胸肉」「它8公斤」「还没打疫苗」「别喂它吃洋葱」等口语与否定边界 |
| `mem-neg-*` | 8 | 否定句：不过敏、不叫、不喜欢吃、没对X过敏、不爱吃 |
| `mem-dialect-*` | 5 | 粤语「佢系我屋企嘅猫，叫糯米」、川渝「它巴适得很，喜欢吃冻干」、东北「我屋头那只猫叫坨坨」等 |
| `mem-multi-*` | 4 | 一个用户多只宠物互不串味，含 `min_confidence=0.8` 的过滤用例与 `ops=["add","update","add"]` 序列校验 |

### 2.2 抽取规则（用例先红，再改）

第一次跑新套件的结果是**红的**，12 条失败，归类后是 5 个真实缺陷。修 `backend-agent/app/memory/extract.py`：

| # | 缺陷（修前） | 用例 | 修法 |
| --- | --- | --- | --- |
| 1 | 问句被当名字：`它叫啥` → `pet_name=啥`、`它叫什么名字？`→`什么名字` | `mem-ext-05`、`mem-ext-06` | `_QUESTION_HEAD = (?!什么|啥|谁|哪|几点|多少)` 加在 `叫` 之后 |
| 2 | 过敏值吞程度副词：`对花生有点过敏` → `allergy=花生有点` | `mem-ext-13` | `_clean_value` 里 `_TRAILING_ADVERBS`（有点/有一点/稍微/些微/可能/应该/一些/一点）循环剥离 |
| 3 | 食物偏好值带动词：`它最爱吃冻干`→`吃冻干`、`它特别喜欢吃鸡胸肉`→`喜欢吃鸡胸肉` | `mem-ext-17`、`mem-ext-18`、`mem-dialect-03` | `food_like` 正则改成 `(?:爱吃|喜欢(?:吃|啃|喝|舔)|爱啃|爱喝)`，动词留在触发词里 |
| 4 | 裸 `喜欢` 过宽：`我喜欢小猫` → `food_like=小猫` | `mem-ext-26` | 同上去掉裸 `喜欢X`；**取舍**：`它喜欢冻干` 这类不带吃的动词的句子从此漏抽，精确率优先 |
| 5 | 否定句全漏：`对鸡肉不过敏`→`花生不`… 等 5 条 | `mem-neg-01/03/04/06/08` | ①`_NEG_BEFORE = (?<![不没未非])` 加在 `叫`、`对…过敏`、爱吃族前面；②值尾属于 `_NEG_TAIL="不没未非"` 时整条丢弃；③`food_avoid` 去掉人称与动词前缀（`别喂它吃洋葱` → `洋葱`，`mem-ext-28`） |

两个中途踩到的坑，写在这里免得下轮重犯：

- `_NEG_BEFORE` 最初含「别」，结果 `它特别喜欢吃鸡胸肉` 里的「特别」被当成否定词，用例从 74% 涨到 98% 后卡在 46/47。最终不含「别」：它既是否定又是「特别/分别」的一部分，误伤比漏判更常见。
- 值前面还可能再跟一个动词（`爱吃` 或裸 `吃`、`喜欢` 或 `喜欢吃` 都会出现）。这种事不能全靠「事后剪前缀」：那要枚举吃/喝/啃/舔，而且会把食物名首字误剪。所以让触发词把动词吃掉（`喜欢(?:吃|啃|喝|舔)`），只在句式固定的 `food_avoid`（`别喂它吃X`）里做人称/动词的前缀剪裁。

## 5. 已知风险与环境坑

1. **裸「喜欢X」不再抽**：`它喜欢冻干` 这种句子现在是漏抽。这是刻意的取舍——`我喜欢小猫` 被写成食物偏好会长期污染记忆，而漏抽只是一次少记。要回收这部分召回率，正确做法是上「按宠物主语切句 + 食物词表」，不是把裸 `喜欢` 加回来。
2. **阈值 0.9 会放走回归**：48 条里最多允许 4 条失败（44/48 = 91.7% 仍绿）。加用例时如果只在末尾追加，可能出现「新用例全过、老用例悄悄坏了 3 条」仍然绿的情况。下一轮建议把阈值提到 0.95（允许 2 条）。
3. **方言覆盖薄**：3 种方言各 1–2 条，且都是我自己造的句子，不是母语者语料。
4. **`text` 用例要求集合全等**：同义词（`花生` vs `花生米`）会被判失败。这是有意的（抽取值要能进档案），但意味着改规则的收益可能被表述差异吃掉。
5. **环境坑（值得写进 AGENTS.md 的那类）**：本机沙箱下子进程写 `%TEMP%` 会被拒，`tempfile.gettempdir()` 会**静默回退到当前目录**。表现是 `pytest --junitxml=$env:TEMP\x.xml` 报 `PermissionError: [Errno 13] ... petlumina-pytest.xml`，且 `$env:TEMP` 里没有文件——文件其实落到了 `backend-agent/` 里（本轮已清理 `dsh-probe-01.txt`、`petlumina-pytest.xml`）。以后要落临时文件，一律用仓库内 `.tmp-` 前缀。
6. **控制台中文**：pwsh 里 `Get-Content` 直接读 python 的日志会把 `(阈值 90%)` 显示成乱码（`(��ֵ 90%)`），因为子进程按 GBK 写管道。加 `-X utf8` 或读 `evals/reports/latest.json` 即可。
