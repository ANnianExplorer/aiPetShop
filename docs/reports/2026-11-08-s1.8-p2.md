## 3. 真实缺陷（不是"顺手修"，是拦下会出事的问题）

| # | 现象 | 根因 | 处置 |
| --- | --- | --- | --- |
| D1 | Redis 侧一接真机就报 `ResponseError unknown command 'HELLO'` | `redis-py 8.x` 默认 RESP3 握手，Redis 5 不支持 | 统一走 `create_redis(protocol=2)`；文件头写明"测试替身发现不了这个故障" |
| D2 | 幂等测试第二次请求仍新建会话、重新执行 | 唯一键按 `(session_id, key)`，而首次请求失败时会话可能还没建出来，客户端只有 key | 去重维度改 `(user_id, key)`，DDL、仓储协议、runner、测试同步改；已建库执行迁移 |
| D3 | `runner.py` 被写成 0 字节 | PowerShell 里用 `[System.IO.File]::WriteAllText` + 拼接的 `$t.Replace(...)`，其中 `.NET` 用的是进程工作目录而不是 `$PWD`，读失败后 `$t` 为 `$null`，写回即清空 | 从 `git checkout` 恢复（P1 版本）后逐段重放 P2 改动；**代码改动改用 edit 工具**，不再用脚本拼字符串 |
| D4 | MySQL 契约测试 `int('run-1')` 抛 `ValueError`，`finish_run` 变成 500 | 桩数据用了非数字 id，而真实 id 空间是 19 位雪花 | 契约测试改用形如 `9999999999999999999` 的合法但不存在的 id；`finish_run` 对非数字 id 抛 `NotFound`（语义上"不可能存在"）而不是崩 |
| D5 | `ruff` 报 `RUF100 unused noqa: BLE001` | 冒烟脚本里照抄了未启用的规则豁免 | 移除豁免，`ruff --fix` 后全绿 |

## 5. 设计决策回顾

1. **幂等按用户而不是会话**：会话是"执行结果"，key 是"意图"；意图先于结果存在，去重必须挂在意图上。
2. **回放优先事件流，退化到库**：重试的语义是"让我看到上次那份答案"，不是"再答一次"；事件过期时宁可少一个 delta，也不 500。
3. **熔断器必须装配期共享**：按请求 new 一个实例，失败计数永远到不了阈值——这是最容易写出"看起来有熔断"的假实现。
4. **401/422 不计入熔断**：调用方凭据错误不是下游故障，否则一个过期 token 就能把整个后端"熔断"。
5. **Redis 只用 5.0 支持的四个命令**：`INCR`/`EXPIRE`/`XADD`/`XRANGE`，不碰 `HELLO` 与新特性。

## 6. 已知缺口（不藏）

1. 熔断状态是**单实例内存**的：多副本各自计数，需 P3 用 Redis 共享。
2. Redis Stream 的 `maxlen` 只做近似裁剪（`approximate=False` 已显式设置，但 5.0 的裁剪精度有限）；极端高频下回放可能少事件，前端有"从库重建"兜底。
3. MySQL 契约测试会向 `petlumina` 库写入测试会话/run（按 user 隔离，不删业务数据）；生产库应使用独立 schema。
4. `memory_fact` 的 upsert 仍用 `VALUES(col)` 语法，MySQL 8.0.20+ 会告警"deprecated"（不是错误）；保留是为了兼容 5.7。
5. 未做压测：并发同 key 的竞争窗口靠唯一键兜底，但没有 100 并发的实测数据。
6. 事件流与配额共享一个 Redis 库（db0），生产建议拆库或加前缀隔离（键已带 `agent:` 前缀）。
