## 5. 关键设计决策回顾

1. **配额与 token 预算分层**：次数挡刷量，预算挡单次长对话；只做一层都可被绕过。
2. **事件存储两实现同契约**：内存版给单机开发，Redis Stream 给多副本；`after`/`Last-Event-ID` 在两种实现上语义一致，测试用同一组断言跑两遍。
3. **记忆宁可少记**：规则抽取 + 置信度阈值 + 三态算子；低置信度不进 system 提示；召回/写入异常一律降级，绝不影响当轮回答。
4. **记忆可核对**：新增 `GET /agent/memory/me`，把"记住了什么"变成可查接口——这不只是给用户看，也是抽取质量的验收面。

## 6. 已知缺口（明说，不糊过去）

| 缺口 | 影响 | 下一步 |
| --- | --- | --- |
| 幂等键未做 | 客户端重试可能重复计费 | P2：`Idempotency-Key` → 复用首次 run |
| 熔断未做 | Java 抖动会拖慢工具链 | P2：连续失败计数 + 半开 |
| Redis 实现只用 FakeRedis 验过 | 真 Redis 的命令细节（`XADD` 选项）未联调 | 起 Redis 后跑同一组契约测试 |
| MySQL 版记忆/用量 SQL 未在真库跑 | 唯一键冲突与 `VALUES()` 语法未实证 | 本机装 MySQL 后执行 `v2.11-agent-memory.sql` |
| 多副本未实测 | 事件流跨进程续传只是设计 | P2：两副本 + 同一 Redis 压测 |
| `memory_episode` 未接向量检索 | "上次那件事"类回忆还不会 | P3 |
