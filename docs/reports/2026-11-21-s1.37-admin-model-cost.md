## 1. 结论

`GET /agent/admin/usage` 在原有全局用量、按日用量之外新增 `by_model`，管理端会话工作台可以看到「近 N 天每个模型花了多少 token、按配置单价估算多少美元」。成本是**展示估算**，不是财务结算：单价由部署环境变量 `PET_AGENT_MODEL_PRICES`（USD / 1M tokens）提供，未配置的模型返回 `cost_usd=null`，界面显示「未配置」，没有拿 0 冒充免费。

本轮没有改 App 侧代码，也没有改 Java 业务后端；App 176 项测试沿用上一轮结果，不重复冒充本轮验证。

## 4. 未覆盖与风险

- **MySQL 变体未跑**：本机无 `PET_AGENT_TEST_MYSQL_DSN`，新查询只在代码层与内存实现上验证；上线前需在真库跑一次契约测试。
- **成本是配置快照**：调整 `PET_AGENT_MODEL_PRICES` 会重算历史展示成本，不对账、不落结算表；缓存折扣、阶梯价、汇率都不在范围内。
- **模型名漂移**：`agent_run.model` 取运行时模型名，改名后历史行会分成两行；这是现状，不做别名合并。
- **管理端无自动化测试框架**：本轮以 `vue-tsc -b` + `vite build` 作为门禁，表格交互没有 DOM 级用例。
- **`dist/` 为构建产物**：管理端构建输出按现有仓库习惯处理，未把它当源码评审。
