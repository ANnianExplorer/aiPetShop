## 4. 本轮抓到的真实缺陷

| 缺陷 | 表现 | 修复 | 防复发 |
| --- | --- | --- | --- |
| 图跳过 `prepare` | L2 时模型第一次调用拿到空 `messages`，一个工具都不调；45 个单测全绿 | `route → prepare` 改为必经边 | `test_graph_l2.py` 断言"首条 system、末条本轮问题" |
| 工具顺序断言过强 | `ToolRegistry.names()` 返回集合序，断言失败 | 改为 `set()` 比较 | 断言只锁"清单存在" |
| 副作用工具语义 | 默认策略下先撞 `tool_not_allowed` 而不是 `requires_confirmation` | 测试显式开 `allow_side_effects=True`；新增"默认部署不暴露写工具"用例 | 两条用例并存 |
| 路径注入 | `pet_id="../../etc/passwd"` 曾被判 `ok:true` | `PetScopedArgs.pet_id` 加 `pattern=^\d{1,19}$` | evals `safe-04` 断言 `invalid_arguments` |

## 5. 已知缺口与风险

| 缺口 | 影响 | 计划 |
| --- | --- | --- |
| 未接真 DeepSeek 模型 | 只验证了协议与桩，未验证真实 token 计费/流式细节 | 配密钥后跑同一套 e2e |
| 未接真 Java（本机无 JDK） | 真实字段/分页行为未验 | 有 JDK 后切 `backend_base_url` 跑冒烟 |
| MySQL 仅契约测试 | 真库字符集/时区未验 | 有 MySQL 后 `PET_AGENT_TEST_MYSQL_DSN` 跑同一套契约 |
| 事件缓冲在进程内 | 多副本无法续传 | S2 换 Redis pub/sub |
| 无 Langfuse 追踪 | 排查只能看日志 | S2 接入 |
