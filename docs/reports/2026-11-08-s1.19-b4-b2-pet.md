## 2. B4：失败退避 + 有界死信重投

### 2.1 改了什么

| 关注点 | 实现 |
| --- | --- |
| 退避公式 | `backoff_seconds(attempt, base=5, cap=600) = min(base·2^(attempt-1), cap)`，`attempt<=0` 按首次算 |
| 退避存储 | Redis `{prefix}:{topic}:retry`（ZSET，score = 到期时刻）；内存实现是 `dict[topic, list[(due, msg)]]` |
| 到期提升 | 巡检 `retry_due()` 每 tick 把到期项搬回主队列（`zrangebyscore → zrem → lpush`）；搬回时**不**重置 attempt |
| 死信 | 超过 `max_attempts` 进 `:dead`；`redrive_dead_letters()` 按 `redrives` 上限重投，达上限留在死信 |
| 自动重投开关 | `TASK_DLQ_REDRIVE_INTERVAL_S`，默认 `0`（关闭）；打开后每 N tick 跑一次，`TASK_DLQ_REDRIVE_LIMIT` 控每轮条数 |
| 可观测 | 日志 `task retry scheduled`（含 `delay_s`、`attempt`）、`task dead letters redriven`；worker 计数器 `promoted` / `redriven` |

### 2.2 为什么不能「nack 后立刻重投」

立刻重投在下游抖动时会变成热循环：一次故障被放大成每秒数千次重试。指数退避把压力摊平，同时用 `cap` 保证不会退避到"永远不重试"。

## 4. C6：桌宠（档 A：H5 + SVG）

## 7. 已知缺口

1. **冒烟脚本身份来源不统一**：6 个脚本写死 `token-*`（桩身份），要跑必须让 8099 指向 8097；只有 `multi_replica_smoke` 走真 Java 登录。后续应统一为"真登录优先，`PET_SMOKE_STUB=1` 才用桩身份"。
2. **熔断不跨副本**：多副本各自计数，同一副本连续失败才会熔断。
3. **桌宠仅档 A**：无 Live2D/VRM，无语音，无主动推送（只在页面挂载时说话）。
4. **死信自动重投默认关闭**：生产要显式打开并观察 `redriven` 指标。
5. **未做压测**：退避与重投的吞吐没在十万级队列上验证。
