## 1. 结论

D10 的第一刀按计划交付：全站底部导航从鼠标专用的 `div` 变为可键盘操作的原生按钮，并带导航名称与当前页标记；Toast 具备 live region，错误提示可即时播报；通用设置页补齐 `h1`、返回按钮名称、两个开关的 `switch` 语义，以及语言弹窗的 `dialog` 语义、打开聚焦、`Tab` 圈定、`Esc` 关闭和焦点归还；全局样式补了统一键盘焦点环与 `prefers-reduced-motion` 降级。

**这只覆盖「全站外壳 + 一个代表性表单页」**，不等于 D10 全站审计完成。社区卡片、日志卡片、图片 `alt`、对比度、真实读屏人工验收仍留在 BACKLOG。

设计取舍：

- 导航用原生 `button` 而不是给 `div` 补 `role="button"` + `tabindex`，直接获得 Enter/Space 与焦点行为，少一层手写键盘逻辑。
- Toast 容器统一 `role="status"`，错误条目再加 `role="alert"`；不把整个容器设成 `alert`，避免成功提示打断读屏。
- 弹窗焦点圈定内联在设置页，不抽全局 composable：目前只有这一个弹窗，抽出去反而增加抽象面；做法与 `ChatView` 历史面板一致。
- 全局 `:focus-visible` 放在 `@layer` 外，才能压过页面里的 `outline-none`；`prefers-reduced-motion` 用 `!important` 是全局兜底，属有意的可访问性优先取舍。
- 不引入 axe-core / Playwright a11y 扫描，本轮只锁 DOM 契约；真实读屏与对比度必须人工验收。

## 4. 未覆盖与风险

- **真实读屏未验收**：jsdom 只能证明属性、焦点位置与 DOM 结构，不能证明 NVDA/VoiceOver 的实际朗读顺序与语气。需要真机人工过一遍。
- **视觉回归未人工核对**：导航从 `div` 改 `button` 已显式重置 `border` / `background` / `font` / 颜色，构建通过，但本轮没有浏览器点击环境，未做像素级对照；建议下次在 Edge 里看五个 tab 的间距与按压缩放。
- **对比度未审计**：`#4b6455` 焦点环对亮色背景、`#89a392` 对暗色背景是人工选值，未跑 WCAG 对比度计算；D10 剩余。
- **其余页面未覆盖**：社区/日志卡片点击区、图片 `alt`、表单错误播报、路由 `document.title` 仍在 D10 待办；本轮不声称全站无障碍达标。
- **`dist/` 随构建更新**：仓库跟踪 `pet-lumina-app/dist`（GitHub Pages 用），构建产物一并提交，属预期。

## 5. 下一步建议

1. 在 Edge 里人工走一遍：键盘 Tab 到导航 → Enter 切页；打开语言弹窗 → Tab 循环 → Esc 关闭看焦点是否回到触发按钮；系统开启「减少动态效果」后看首页光晕/呼吸动画是否停止。
2. 真机 + NVDA（Windows）/ VoiceOver（iOS）：确认导航名称、`aria-current`、Toast 播报、开关状态的实际朗读。
3. D10 下一刀建议按「页面族」推进：先社区/日志卡片（`div @click` 与图片 `alt`），再表单错误播报与路由标题，最后做对比度扫描与读屏人工验收。
