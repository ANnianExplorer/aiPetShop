# S1.26 报告：docker build 的构建上下文（BACKLOG C8）

## 一句话

GitHub 提交列表里那些红叉不是代码坏了，是 CI 里 `docker build` 的路径写重了：从 S1.6 起 34 次运行 34 次红，唯一挂的永远是同一步。

## 怎么查的（可复现）

```bash
# 1) 这个 workflow 的运行历史：34 次，全部 failure
curl -s https://api.github.com/repos/ANnianExplorer/aiPetShop/actions/workflows/410077834/runs?per_page=40

# 2) 某一次失败运行的两个 job：check 绿、docker build 红
curl -s https://api.github.com/repos/ANnianExplorer/aiPetShop/actions/runs/43605978650/jobs

# 3) 失败的步骤只有 "Build image"；注解里只有 "Process completed with exit code 1."
#    真正的错误在 job 日志里（需 token：git credential fill 拿 gho_ 令牌后带 Authorization）
curl -s -H "Authorization: Bearer <token>" \
  https://api.github.com/repos/ANnianExplorer/aiPetShop/actions/jobs/132480723273/logs
```

日志原文：

```
##[group]Run docker build -t pet-agent:ci backend-agent
docker build -t pet-agent:ci backend-agent
shell: /usr/bin/bash -e {0}
ERROR: failed to build: unable to prepare context: path "backend-agent" not found
##[error]Process completed with exit code 1.
```

## 根因

`.github/workflows/agent-ci.yml` 顶层有 `defaults.run.working-directory: backend-agent`，所有 `run` 步骤的 cwd 已经是 `backend-agent`。
`image` job 里又写 `backend-agent` 作构建上下文 → 实际解析成 `backend-agent/backend-agent`，不存在。

## 改动

| 文件 | 改动 |
|---|---|
| `.github/workflows/agent-ci.yml` | `docker build -t pet-agent:ci backend-agent` → `docker build -t pet-agent:ci .`（附注释说明 cwd 已被 defaults 设定） |
| `.github/workflows/agent-ci.yml` | `on.push` 增 `branches: [main]`：推标签不再重复触发同一个提交的 CI |

Dockerfile 本身没动：`backend-agent/Dockerfile` 的 `COPY requirements.txt` / `COPY pyproject.toml` / `COPY app` 都在上下文根下，`.`

## 已知风险 / 未做

- 本机没有 docker，无法在本地复现 `docker build`；验证完全依赖 Actions 的真实结果（上面那次）。
- 镜像只验证了「能构建」，**没有真启动容器跑 `/healthz`**（本地无 docker，也没做容器编排验证）。
- CI 仍不跑前端（`vue-tsc`/`vitest`/`build`）与 `backend/` 的 `mvn test`，只覆盖 `backend-agent`；扩到全仓是 C8 之外的新需求。
- 依赖版本浮动导致的偶发变红属于长期维护，本次未加锁版本校验。
