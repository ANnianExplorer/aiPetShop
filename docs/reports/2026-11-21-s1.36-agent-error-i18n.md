## 5. 未覆盖与风险

- **管理端 / Java 未纳入**：`pet-lumina-web` 与 Java `/api/v1` 的错误文案仍是中文；本轮只覆盖 App Agent 链路，避免范围膨胀。
- **翻译为手写**：三语文案未经过母语者校对；英文/日文占位与语序需后续人工过一遍。
- **未做真机语言切换**：jsdom 能证明 key 与插值正确，不能证明真机上切语言后已渲染的错误条会即时刷新（当前错误文案在事件发生时求值）。
- **`detail` 只建模了 `retry_after_s`**：服务端 `rate_limited` 还带 `scope`/`limit`，`circuit_open` 还带 `breaker`，本轮不透出；后续若要做「限流原因」展示需扩展类型。
- **服务端 message 仍是中文兜底**：未知 code 会显示中文；这是有意的降级路径，不是遗漏。
- **`dist/` 已随构建更新**：仓库跟踪 `pet-lumina-app/dist`（GitHub Pages 用），本次构建产物一并提交，属预期。

## 6. 下一步建议

1. 用真机切 en-US / ja-JP 走一遍：发送触发 `rate_limited`、网络断开、上传失败、删除记忆失败，确认错误条即时刷新且无中文残留。
2. 把「英文界面 + 429 + retry_after_s」补进 Playwright e2e（S1.32 已有三进程脚手架）。
3. 管理端与 Java 错误的 i18n 单独立项：先统一错误码表，再决定是否复用 App 的 `agentError.*` 文案。
4. 若产品需要展示限流维度，再扩展 `detail` 类型（`scope`/`limit`/`breaker`），不要提前加无用字段。
