# S1.21 图片生成桌宠 交付报告

日期：2026-11-08
状态：已完成
关联：`docs/plans/s1.21-image-to-pet.md`

## 1. 需求与判断

用户要的不是「再画一个」：

> 不好看，我需要的是可以根据图片生成一个桌宠

所以本轮把桌宠形象来源换成**用户自己的图**：上传 → 自动抠背景 → 卡通化 → 变成首页右下角的桌宠。

先明确三档路线的能力边界（写在计划文档 §1）：

| 档 | 做法 | 上限 |
| --- | --- | --- |
| **A（本轮）** | 浏览器端像素管线 + 整图级动效 | 形象 100% 来自用户图；**没有骨骼形变，眨眼/口型做不了** |
| B | 切层绑定 Live2D | 真·灵动，但需人工切层或自动分层模型 |
| C | 单图重建 3D/VRM | 需 GPU 与生成模型 |

本轮交付 A，并把精灵图来源抽象成「一段 dataURL + 尺寸」，后续 B/C 产出可以直接替换。

## 2. 管线（`src/utils/petImage.ts`，全部纯函数）

```text
File → ImageData
  ├ 1. removeBackground：四角均值取背景色 + 边缘 flood fill（内部同色不误删）
  ├ 2. alphaBounds / cropImage：按 alpha 求包围盒，留 8px 透明边距
  ├ 3. cartoonify：3×3 平滑 → 色阶量化（默认 6 阶）→ 饱和度 1.12
  ├ 4. outlineImage：Sobel 梯度 → 压暗勾边（默认 0.6，可关）
  └ 5. scaleDown：长边 ≤ 512（面积平均，只缩不放）
```

关键取舍：**从四角做连通洪泛**而不是「按颜色全图擦除」。否则白猫的白肚皮会被当成背景一起删掉——单测 `只删与边缘连通的部分（内部同色不误删）` 专门钉住这一点。

## 3. 交互与动效

| 能力 | 实现 |
| --- | --- |
| 上传 / 预览 / 保存 / 恢复默认 | `src/views/pet/PetStudio.vue`（路由 `/pet-studio`，个人中心入口「用图片生成桌宠」） |
| 三个可调参数 | 背景容差 0–120、色阶 2–12、描边 0–1；每次调参用**原图数据**重跑，不在结果上叠滤镜 |
| 精灵图动效 | 呼吸（scale 1→1.02，3.8s）+ 摇摆（±1.1°）+ 椭圆影子反向缩放；`prefers-reduced-motion` 全关 |
| 与内置角色共存 | `DeskPet.vue` 有图用图，无图回退 `ChibiPet`（7 部件动画版） |
| 存储 | `localStorage['petlumina-deskpet-sprite']`，保存前校验结构；配额不足返回 `quota` 并提示换小图 |

**隐私**：图片只在浏览器 canvas 里处理，不上传服务器、不进对话记忆；删除即从 localStorage 移除。

## 6. 已知边界（说清楚，不粉饰）

1. **不会眨眼、不会说话**：单张图没有可动的眼睛与嘴，硬贴黑线只会更假。
2. 抠背景对复杂背景（毛发边缘、渐变、条纹）效果有限，需要更干净的底图；没有手动涂抹修正。
3. 动效是整图级（呼吸/摇摆/影子），比内置 7 部件角色「活」得少。
4. 目前只支持静态图（PNG/JPEG/WebP），不支持 GIF 动图或视频。
5. 图像只在本地，多设备不同步。
