# S1.25 引用回跳：locator 变成 App 路由（BACKLOG C4）

> 日期：2026-11-14 ｜ 批次：S1.25 ｜ 短名：citation-jump-links
> 计划：[`docs/plans/s1.25-citation-jump-links.md`](../plans/s1.25-citation-jump-links.md)

## 1. 目标

对话里出现引用时，点下去要能落到能核对的页面；新增引用来源不用改前端。

## 2. 为什么只改前端不够

改之前三处事实（`docs/plans/s1.25-citation-jump-links.md` §2）：

1. `ChatView.vue:229` 只认 `kind === 'log'`；
2. 工具的 `locator` 是给人看的字符串（`"宠物档案"`、`"petId=5001"`），前端没法当路由用；
3. 帖子工具**不存在**，所以“帖子引用能跳详情”拿不到来源。

结论：`locator` 的语义要升级成「App 内路由」，帖子引用要补一个只读工具。

## 3. 改了什么

| 文件 | 改动 |
| --- | --- |
| `backend-agent/app/tools/pet.py` | 三个工具的 `locator` 改成路由；新增 `_fmt_date()`（毫秒时间戳 / `yyyy-MM-dd HH:mm:ss` 归一成 `yyyy-MM-dd`）；新增 `search_posts` + `SearchPostsArgs`（走 `POST /post/list/page/vo`）并注册 |
| `pet-lumina-app/src/utils/citationRoute.ts`（新） | `citationRoute(citation): string | null`：路由优先，老数据按 kind 兜底，兜不住返回 `null` |
| `pet-lumina-app/src/views/chat/ChatView.vue` | `openCitation` 改调 `citationRoute`，删掉 `kind === 'log'` 分支 |
| `pet-lumina-app/src/views/wellness/WeeklyHealthDetail.vue` | 读 `petId`/`date`：优先用 query 里的宠物；命中那天加 `ring-2 ring-primary` 并 `scrollIntoView` |
| 三个 locale | 补 `tool.search_posts` 文案 |
| `backend-agent/tests/conftest.py` | 桩 Java 增加 `/api/v1/post/list/page/vo` |
| 测试 | `tests/test_citations.py`（新，7 例）、`test_api.py`/`test_graph_l2.py` 工具集合更新、`citationRoute.spec.ts`（新，5 例） |

引用路由一览：

| kind | locator |
| --- | --- |
| pet | `/pet-detail/{id}` |
| post | `/post/{id}` |
| log | `/log/{id}` |
| health | `/weekly-health-detail?petId={id}&date={周记录里最大的日期}` |

## 4. 不变量 L1–L5

- L1 `/` 开头即路由，前端原样 push；
- L2 老数据无路由时 `log`/`post`/`pet` 按 kind 兜底；
- L3 兜不住返回 `null`，只显示 label，不假装能跳；
- L4 健康引用日期取周记录最大值，不取“今天”（看板可能是补录）；
- L5 帖子工具只读、不按宠物过滤。

## 6. 过程记录（失败与修正，如实写）

1. 第一次冒烟 `E2E_EXIT=1`、`names1` 为空：三段时间只起了服务，但设的是 `AUTH_MODE=header` 却没带 `x-user-id` → 请求被 401。
   改成 `AUTH_MODE=backend`（让 `satoken` 去 `/auth/current`）后 10/10。
2. ruff 报 `test_citations.py` 导入顺序（I001），`--fix` 修掉。
3. `test_graph_l2.py` 断言「发给模型的工具集合」是三条旧工具，加入 `search_posts` 后必须同步更新——这条断言是故意的：工具集变了就应该有人看。
4. 健康引用最初想用“今天”当日期，写测试时意识到看板可能是补录数据，改成取周记录最大值。
