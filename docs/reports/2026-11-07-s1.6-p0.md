## 1. 本轮改了什么

| 文件 | 变更 | 为什么 |
| --- | --- | --- |
| `app/core/logging.py` | 新增：`JsonFormatter` + `log_event` + 三个 contextvar | 出问题要能按 `request_id/run_id` 串起来，而不是 SQL 与文本日志手工对 |
| `app/api/observability.py` | 新增：`RequestContextMiddleware` | `x-request-id` 透传/生成、访问日志、错误响应也带 id |
| `app/api/routes.py` | 新增 `GET /readyz` | 区分"进程活着"与"能接流量"；依赖坏了要 503 而不是假装 200 |
| `app/storage/{base,memory,mysql}.py` | 新增 `ping()` | 就绪探针真的执行 `SELECT 1`，不是看连接池对象是否存在 |
| `app/runtime/runner.py` | 加 run 开始/结束/失败日志；`try/except pass` → `contextlib.suppress` | 排障需要 `route/steps/tokens/latency`；吞异常必须显式 |
| `app/tools/gateway.py` | 工具调用日志（工具名/耗时/摘要/错误码） | 工具是外部依赖，慢和失败要能单独看到 |
| `app/api/app.py` | 装配中间件 + `configure_logging`；修正中间件顺序 | 后加的先执行：CORS 在内层、请求上下文在最外层 |
| `app/config.py` | 新增 `PET_AGENT_LOG_LEVEL` | 日志级别不该写死在代码里 |
| `requirements.in` / `requirements.txt` / `requirements-dev.txt` | 意图 + 精确锁定 + 开发依赖三分 | 原来只有 `>=`，换个日期装出来就是另一套依赖 |
| `Dockerfile` / `.dockerignore` | 多阶段、非 root、`HEALTHCHECK` | 交付物必须能部署；容器里跑 root 是红线 |
| `.github/workflows/agent-ci.yml` | ruff → pytest → evals → docker build | 没有自动门禁的"我本地是好的"不算证据 |
| `tests/test_observability.py` | 10 例 | 把 `x-request-id`、日志字段、`/readyz` 两种降级路径钉死 |
| `tests/test_mysql_dsn.py` | 4 例 | 钉住 DSN 解析与 `aiomysql` 可导入 |

## 2. 顺手抓到的真实缺陷

| 编号 | 缺陷 | 发现方式 | 修复 |
| --- | --- | --- | --- |
| D1 | `aiomysql` 在 `requirements.txt` 里但**从未安装**；懒加载 import 让所有测试都绿 | 新增 `test_mysql_dsn.py` 前用 `pip freeze` 对照 | `pip install aiomysql==0.3.2` 并精确锁定；补 `test_aiomysql_available` |
| D2 | 中间件顺序写反（请求上下文在内层），CORS 预检响应拿不到 `x-request-id` | 写代码时对照 Starlette「后加先执行」 | CORS 先加、`RequestContextMiddleware` 后加，并在注释写清原因 |
| D3 | `/readyz` 首版只在内存实现上有意义（没有 `ping`），MySQL 挂掉仍会 200 | 设计评审：探针必须打真实依赖 | 协议加 `ping()`，MySQL 版执行 `SELECT 1` |
| D4 | 新增测试首版 7 例忘记 `await`（`httpx.AsyncClient.get` 返回 coroutine） | `pytest` 报 `'coroutine' object has no attribute 'status_code'` | 全部改 `async def` + `await`，并在 `test_log_event_writes_ctx...` 用同步 `LogRecord` 验证格式化器 |
